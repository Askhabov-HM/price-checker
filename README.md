# Price Checker

## Frontend: React + TypeScript

Интерфейс использует React, TypeScript, Vite, TanStack Router и TanStack Query.
Компоненты shadcn/ui оформлены через Tailwind CSS, графики построены на Recharts.
Zustand сохраняет только предпочтения интерфейса; товары и историю кеширует TanStack Query.
Поле Cookie Randewoo не сохраняется в browser storage и очищается при закрытии настроек.

`PriceChart`, `ProductTable` и `DetailDialog` реализованы как compound components
с общим состоянием через Context: `Root` и вложенные части (`Toolbar`, `Plot`, `History` и другие).
Компоненты shadcn/ui находятся в `frontend/src/components/ui/` и доступны для изменения.

```powershell
npm ci
npm run auth:setup
npm start
```

Сборка сохраняется в игнорируемом `dist/`, Node.js раздаёт её вместе с API.
Прямой запуск `node run.js`, Windows-автозапуск и `npm run lab` автоматически
пересобирают отсутствующий или устаревший frontend. Маршруты `/cart`, `/my-cart`, `/favorites`
и `/watching` поддерживают прямое открытие и перезагрузку. Фильтры, поиск,
период и тип цены сохраняются в URL; шкала графиков — локально в браузере.

«Моя корзина» (`/my-cart`) — отдельная локальная подборка пробников. Добавляйте и
убирайте варианты кнопкой корзины в таблице или добавляйте ссылку на товар из этой
вкладки. Состав хранится в SQLite и сохраняется после перезапуска и синхронизации
Randewoo. Цены и история берутся из публичных проверок. Корзина Randewoo (`/cart`)
по-прежнему получает свой состав и цены из аккаунта сайта. В обеих корзинах флажок
«Скидка 10%» пересчитывает итог доступных пробников, без доставки. Выбор сохраняется
отдельно для каждой корзины в браузере; история и исходные цены сохраняются без
применения промокода.

Фильтры «Изменились недавно», «Подешевели» и «Подорожали» учитывают последнее
ненулевое изменение цены за 7, 14 или 30 дней (по умолчанию — 7). Повторная
проверка с той же ценой не сбрасывает отметку. В таблице показаны цены до и после
изменения, сумма, процент и время обнаружения. Счётчики снижений и повышений
включают соответствующий фильтр по нажатию. Ошибки и отсутствие варианта не
удаляют сохранённое событие; состояние последней проверки показано отдельно.
Период изменений не зависит от периода графика товара. Цены сайта и корзины
сравниваются отдельно; первое измерение не считается изменением цены.

Для разработки запустите `npm start` в одном терминале и `npm run dev` в другом.
Vite выводит адрес dev-сервера и перенаправляет `/api` на `127.0.0.1:8000`.
Прокси меняет Origin только в режиме разработки, чтобы API сохранял проверку
локального адреса и CSRF-токена.

```powershell
npm run check           # TypeScript и синтаксис backend
npm test                # Сборка, node:test и Vitest + React Testing Library
python -m unittest discover -s tests -p 'test_*.py'
```

Запуск e2e и браузерных тестов запрещён правилами проекта. CI выполняет сборку,
статические проверки и unit-тесты без запуска браузера; шаги Playwright удалены.

## Ozon: `/ozon`

Страница `/ozon/browser` (пункт «Браузер Ozon») показывает состояние серверного
браузера, адрес, заголовок и снимок страницы. Доступ требует входа в Price Checker.
Кадры обновляются раз в 5 секунд только в видимой вкладке; просмотр не запускает
Chrome и не меняет открытую страницу. При ошибке сбора сохраняется один последний
снимок; непрерывной записи нет. Окно ввода кода доступно отдельно на `/ozon/login`
и здесь не записывается. Подробности: [наблюдение за браузером](docs/ozon-browser-monitor.md).

Раздел `/ozon` доступен через переключатель в боковой панели и защищён общим входом
в Price Checker. Основной список показывает всё избранное, цену Ozon и зачёркнутую
цену, график и историю цен. Доступны фильтры и сортировки как у Randewoo: изменения
за 7/14/30 дней, снижение и рост цены, исторический минимум, недоступные товары
и позиции без свежих данных. Минимум и последнее изменение рассчитываются по всей
сохранённой истории выбранного типа цены. В колонке «Последнее изменение» показаны
сумма и процент роста или снижения, прежняя и новая цена и время обнаружения;
повторные проверки с той же ценой не сбрасывают изменение. Прежние цены недоступных товаров, статусы и точки графиков показаны
синим; ошибки сбора — красным. Отсутствующие товары остаются в слежении через общее избранное.
После возвращения свежая цена сравнивается с последней известной, включая историю до возвращения;
пока товара нет, исходная дата цены сохраняется. Колонка продавца убрана из таблиц. Данные хранятся
физически отдельно в `.data/ozon/prices.sqlite3`; база Randewoo не используется.

Сборщик выполняет HTTP-чтения последовательно, проверяет аккаунт и доставку,
останавливается на 401/403/429 и сохраняет последние успешные цены при ошибке.
В настройках каждого магазина отдельно выбирается один режим: часы по Москве
(чекбоксы 00:00–23:00, где 24:00 совпадает с 00:00) либо интервал 30 минут, 1 час
или 2 часа. У каждого магазина своё включение автоматических проверок; изменения
Randewoo не меняют Ozon и наоборот. При обновлении прежнее время Randewoo 00:30
сохраняется дополнительным отмеченным пунктом. Расписание Ozon **по умолчанию выключено**,
исходный интервал — 30 минут. После перерыва выполняется одна пропущенная проверка.
Обновление приложения само по себе не включает проверки. Одна ручная проверка
18 октября получила HTTP 403; та же единственная карточка затем успешно прочитана
в серверном Chrome, обе цены и продавец сохранены в истории. Chrome закрыт,
полный обход избранных и длительный цикл не запускались.
Настройка и ограничения: [раздел Ozon](docs/ozon-ui.md).

18 октября подтверждено чтение непосредственно в Chrome
на Linux VDS: публичная карточка без входа, а после ручного входа владельца — последние 30
избранных, 3 позиции корзины, тот же аккаунт/адрес, обе цены и продавец одной карточки.
После немедленного перезапуска браузера вход, доставка и порядок 30 избранных сохранились.
Пик памяти с удалённым окном — около 590 МиБ, без OOM. Серверный профиль сохранён приватно,
временные процессы и доступ закрыты: [публичная карточка и вход на Linux](docs/ozon-public-product-linux.md).

После этого HTTP-проверка с новой Linux-сессией тоже прошла: четыре GET из Node вернули
JSON 200 при закрытом Chrome — избранное, корзина, карточка и условия Ozon Карты.
Аккаунт/доставка и обе цены подтверждены; сессия восстановлена новым процессом Node.
Пик RSS около 113 МиБ: [HTTP без работающего Chrome](docs/ozon-http-linux-session.md).
Прежняя диагностическая пауза не снята. Для Ozon, его CDN `ozone.ru` и Randewoo в Mihomo
подтверждён `DIRECT`. Импорт сессии и HTTP-сборщик реализованы; полный проход и длительная
двухчасовая проверка ещё предстоят. История экспериментов и ограничения:
[docs/ozon-feasibility.md](docs/ozon-feasibility.md).

```powershell
npm run ozon:status         # Только локальный статус, без запросов к Ozon
npm run ozon:network -- --preview  # Разбор локального снимка MCP, без сети
npm run ozon:server-check         # Статус серверной диагностики, без сети
npm run ozon:probe          # Один публичный GET главной страницы, без аккаунта
```

Для проверки одной карточки: `npm run ozon:probe -- https://www.ozon.ru/product/…`.
Пауза между диагностическими запросами — не меньше двух часов; состояние сохраняется
в отдельной `.data/ozon/probe.sqlite3`. Публичный HTML-probe останавливается на перенаправлении;
при ограничении доступа требуется проверка владельцем. `npm run ozon:probe -- --acknowledge-pause`
подтверждает такую проверку без сетевого запроса и не сокращает срок ожидания.

Для аккаунтного JSON допускаются только полученные от Ozon перенаправления на тот же
API с неизменной целевой страницей и проверенным параметром `__rr`. Сессии хранятся
приватно в `.secrets/`, с учётом обновления, удаления и срока cookies. Остановка по
403/401, неподтверждённому контексту или прерванному процессу переживает перезапуск.
Для 429 и временных ошибок пауза увеличивается; `Retry-After` имеет приоритет.
HTTP 200 сам по себе не подтверждает цены, авторизацию или доставку: требуется проверка содержимого ответа.
Вход в Chrome на компьютере владельца не подключает аккаунт к серверу автоматически.

Для `--preview` нужен приватный манифест `.secrets/ozon-mcp/capture.json` и сохранённые
ответы JSON рядом с ним; формат описан в отчёте об эксперименте. Команда не создаёт
историю цен и не объявляет эти данные текущими. Настоящие ответы, адрес доставки и
сессия остаются в игнорируемой `.secrets/`, в Git используются искусственные fixtures.
HAR остаётся запасным вариантом импорта, ручной экспорт при подключённом MCP не нужен.

## Проверка тестовой базы и графиков

`npm run lab:verify` создаёт отдельные базы в `.data/test-lab/runs/`: `source.sqlite3` с управляемыми ценами
и `history.sqlite3` с результатами проверок. Тестовый HTTP-источник отдаёт карточку, корзину и избранное
в штатный парсер приложения. Рабочая база и сессия Randewoo в этом режиме не используются.

Проверка открывает настоящий Chrome/Edge без окна, нажимает «Проверить цены», последовательно меняет
цены, проверяет таблицы и рисование графиков, сохраняет скриншоты и `report.md`/`report.json`.
Нужен установленный Chrome/Edge/Chromium; другой путь можно указать в `PRICE_CHECKER_TEST_BROWSER`.
Восемь сценариев: первая цена, снижение, рост, неизменная цена, отсутствие в наличии, возврат в наличие,
ошибка источника и восстановление. После перезапуска отдельно проверяется сохранённая история.

```powershell
npm run lab:verify
npm run lab
```

После проверки `npm run lab` открывает сохранённую тестовую базу на **http://127.0.0.1:8001**.
В отдельном терминале можно изменить цену, а затем нажать «Проверить цены» в тестовом приложении:

```powershell
npm run lab -- --scenario drop
npm run lab -- --scenario rise
npm run lab -- --scenario restored
```

Тестовый аромат: **Test Lab / Graph Eau**, два варианта 1,5 мл. Основная цена меняется
**1000 → 800 → 1200 → 1200 → 1200 → 950 → ошибка → 950 ₽**; цена корзины хранится отдельно.
Вариант 50 мл добавлен для проверки исключения других объёмов. Повторные запуски `lab:verify` создают
новую базу; перед ними остановите предыдущий тестовый сервер через Ctrl+C. Обычные автотесты запускаются через `npm test`.

Локальное приложение на **Node.js** для отслеживания цен Randewoo на варианты
**1,5 мл**. Работает без AI и платных API.

Repository: [Askhabov-HM/price-checker](https://github.com/Askhabov-HM/price-checker).

## CI/CD: Ubuntu

GitHub Actions (`.github/workflows/ci-deploy.yml`) проверяет pull request и push
в `main` и `develop`: типы, синтаксис, сборку, backend, frontend и Python-проверки
скриптов. Проверки выполняются без запуска браузера. После успешных проверок push
в `main` автоматически обновляет сервер
`153.76.171.172`. Ручной запуск доступен в Actions → Check and deploy → Run workflow
или через `gh workflow run ci-deploy.yml --ref main`. Деплой разрешён только из `main`.
Незакоммиченные локальные изменения на сервер не отправляются.

Используется существующая служба `price-checker.service` (пользователь `pricechecker`,
Node.js в `/usr/local/bin/node`). GitHub передаёт проверенные исходники и готовый
`dist/`; зависимости устанавливаются на Ubuntu через `npm ci`. Новая версия
сохраняется в `/opt/price-checker/releases/github-<commit>-<id>`, а ссылка
`/opt/price-checker/current` переключается после установки зависимостей.

Перед переключением служба останавливается, а SQLite копируется через SQLite
Backup API в `data/backups/pre-deploy-*.sqlite3`. После запуска проверяется
`http://127.0.0.1:8000/api/health`. Если запуск или проверка завершились ошибкой,
восстанавливается предыдущая версия кода и workflow завершается с ошибкой.
Автоматический откат не заменяет базу: новая версия могла успеть записать данные.
При несовместимой миграции восстановление базы из копии выполняется отдельно.

Рабочая база, история, сессия Randewoo и прочие секреты остаются в
`/var/lib/price-checker/data` и `/var/lib/price-checker/secrets`. Конфигурация службы,
Telegram и HTTPS-прокси при деплое не меняется. Предыдущие версии и копии базы
сохраняются для восстановления; их очистка выполняется отдельно по мере необходимости.

Однократная настройка для существующего сервера:

1. Создать отдельный SSH-ключ Ed25519 без парольной фразы для GitHub Actions.
2. Скопировать на сервер `scripts/deploy.py`, `scripts/setup-deploy.sh` (в одну
   папку) и публичный ключ. Выполнить от root:
   `bash setup-deploy.sh /path/to/deploy-key.pub`.
3. В Settings → Secrets and variables → Actions создать repository secrets:
   `DEPLOY_SSH_KEY` — приватный ключ; `DEPLOY_KNOWN_HOSTS` — уже проверенная запись
   сервера из `known_hosts`. Не подставлять неподтверждённый результат `ssh-keyscan`.
4. При смене адреса или SSH-порта задать repository variables `DEPLOY_HOST` и
   `DEPLOY_PORT` (по умолчанию `153.76.171.172` и `22`) и обновить запись хоста.

Ключ в `authorized_keys` ограничен `restrict` и фиксированной командой
`/usr/bin/python3 /usr/local/lib/price-checker/deploy.py`: произвольные SSH-команды,
PTY и перенаправление портов для него запрещены. Загрузчик принимает только
`deploy <SHA>` и архив без симлинков, путей за пределами версии, базы и секретов.
Сам загрузчик устанавливается отдельно; push не заменяет его. При изменении
`scripts/deploy.py` повторите установку через `setup-deploy.sh` с тем же публичным ключом.

Проверка сервера: `systemctl status price-checker.service`, логи:
`journalctl -u price-checker.service -n 100 --no-pager`. Коммит активной версии
сохраняется в `/opt/price-checker/current/REVISION`.

## Запуск

Требуются **Node.js 24.14.1 или новее**, npm и **curl** в PATH.
В Windows используется `curl.exe`. Python не нужен.

```powershell
npm ci
npm run auth:setup
npm start
```

Приложение откроется в браузере: **http://127.0.0.1:8000**.
В терминале Ctrl+C завершает работу.

На Windows можно дважды нажать **start.cmd**: приложение запустится в фоне.
При первом запуске скрипт установит npm-зависимости, если они отсутствуют.
Закрытие вкладки браузера не останавливает сбор. Для остановки дважды нажмите
**stop.cmd**: сервер отметит активную проверку как прерванную, закроет базу
и освободит блокировку. Данные сохранятся.

```powershell
npm start -- --no-browser
npm start -- --no-browser --port 8001
```

Другой порт используется после остановки предыдущего экземпляра.

## Возможности

- Корзина и избранное аккаунта Randewoo, включая все страницы избранного.
- Независимый список «Наблюдение»: добавление ссылки или звёздочка у товара.
- Только варианты 1,5 мл. Разные концентрации имеют отдельные артикулы и историю.
- Текущая цена, изменение в рублях и процентах, минимум за историю, наличие.
- График каждого варианта за неделю, месяц, 90 дней или всё время.
- Обзор стоимости списка: по одному доступному пробнику каждого варианта.
  Это не итог заказа с учётом количества, доставки, баллов или промокодов.
- Поиск, сортировка, фильтры снижения/роста/минимума цены, экспорт CSV для Excel.
- Журнал проверок и ежедневная локальная резервная копия SQLite.

По умолчанию проверки выполняются в **00:30, 09:00, 14:00, 20:00 по Москве**.
Время можно изменить или поставить проверки на паузу в настройках. После сна
или перезапуска выполняется одна проверка за последний пропущенный интервал;
исторические цены за время выключения компьютера не восстанавливаются.

**Компьютер должен быть включён, подключён к интернету и не спать.**
Сбор работает, пока запущено приложение. Графики содержат реальные проверки:
при одной точке линия не выдумывается. Ошибки и недоступные варианты не становятся
нулевой ценой. Обзор явно указывает, сколько доступных позиций вошло в сумму.
При изменении состава набора линия прерывается, даже если число товаров прежнее.

В корзине можно переключить **публичную цену на сайте** и **цену варианта в
корзине аккаунта**. Эти истории хранятся отдельно. Основной тип цены — публичная
цена сайта. Удаление товара из списка сохраняет историю в базе.

## Вход в Price Checker

Перед первым запуском настройте логин и пароль для интерфейса:

```powershell
npm run auth:setup
```

Пароль вводится скрыто. В `.secrets/price-checker-auth.json` сохраняются логин,
случайная соль и хэш scrypt; сам пароль не хранится. Файл исключён из Git и должен
переноситься отдельно при развёртывании. При отсутствии или повреждении файла
приложение не запускает веб-сервер. Повторный `npm run auth:setup` меняет доступы;
после изменения перезапустите приложение.

До входа доступны только экран авторизации и проверка работоспособности.
Данные, CSV и операции API требуют действующую сессию. Вход сохраняется на 7 дней
в HttpOnly-cookie; после выхода или перезапуска приложения требуется новый вход.
Ошибочные попытки ограничены: 8 за 15 минут с одного адреса подключения.
Выход из интерфейса не останавливает сбор цен и расписание.

Сервер остаётся на `127.0.0.1`. Для доступа через HTTPS-прокси задайте
`PRICE_CHECKER_PUBLIC_ORIGIN=https://<адрес-сайта>`: приложение разрешит этот Host
и Origin и выставит cookie с атрибутом Secure. Заголовки X-Forwarded-* не используются
для определения доверенного адреса. Тестовый стенд по умолчанию запускается без входа
и не использует рабочие доступы.

## Авторизация Randewoo

В настройках в разделе «Подключение Randewoo» введите российский мобильный номер
аккаунта, нажмите «Получить код Randewoo» и подтвердите полученный код. Для обновления
истёкшей сессии повторите подключение. После входа запустите проверку цен для
синхронизации корзины и избранного.

Перед запросом кода браузер выполняет штатную проверку CAPTCHA Randewoo. При
дополнительной проверке на стороне магазина остаётся ручной способ обновления
Cookie через «Обновить данные авторизации». Новая сессия заменяет действующую
только после подтверждения кода и проверки авторизации на сайте. Номер, код и
промежуточные cookies не записываются в базу или browser storage; незавершённое
подключение хранится в памяти до 10 минут и отменяется при закрытии настроек.
Повторная отправка ограничена минимум минутой и пятью запросами в час;
доступны пять попыток ввода кода на одно подключение. Рассылки не подключаются.

Подтверждённая сессия хранится на сервере приложения в `.secrets/randewoo-session.json`:

```json
{
  "cookie": "<Cookie request header>",
  "user_agent": "<User-Agent request header>"
}
```

Значения берутся из своего запроса `/cart` в Chrome DevTools → Network.
Обновить их можно в настройках приложения. Они не возвращаются интерфейсу,
не выводятся в логи и не передаются curl через аргументы процесса: конфигурация
поступает через stdin. Сессия может истечь; приложение сообщит об этом и сохранит
списки. Публичные цены известных товаров продолжат проверяться без входа.

Изменения требуют CSRF-токен текущей сессии Price Checker.
Веб-интерфейс не предоставляет доступ к файлам сессии, базе или исходникам.

## Ошибки запросов и повторы

Временные ошибки DNS, соединения, тайм-ауты и HTTP 408/429/500/502/503/504
повторяются максимум два раза после первого GET-запроса, с задержкой примерно
1 и 2 секунды. `Retry-After` учитывается; если сервер просит ждать больше 10 секунд,
проверка завершается ошибкой. Ошибки сертификата, авторизации, HTTP 403/404 и
POST-запросы входа автоматически не повторяются. Остановка приложения прерывает
запросы и ожидание повтора.

Каждая попытка пишет JSON-строку `randewoo_request` в stdout: время UTC, путь
без параметров, метод, ID проверки, номер попытки, HTTP-статус, код curl,
категорию ошибки, длительность и решение о повторе. Cookie, User-Agent, номер,
код, CSRF, содержимое ответов и сырой stderr в журнал не попадают. На VDS журнал
доступен через `journalctl -u price-checker`; в локальном запуске — в выводе процесса.
Итог проверки и ошибки товаров сохраняются в SQLite; предыдущие успешные цены
остаются доступными при сбое.

## Данные и переход с Python

- `.data/prices.sqlite3` — общая база товаров, вариантов, списков и наблюдений.
- `.data/backups/` — резервные копии базы, по одной за день.
- `.data/imports/` — первоначальные реальные снимки для однократного импорта.
- `.secrets/` — доступы Price Checker и действующая авторизация Randewoo.
- `scratch/` — временные результаты диагностических скриптов; можно удалять.

Эти каталоги исключены из Git. **Существующая база Python-версии используется
напрямую**: идентификаторы, история, настройки и авторизация сохраняются.
Формат UTC-времени и цены в целых копейках совместимы с прежней версией.
Первые реальные снимки из `.data/imports/` импортируются один раз при создании новой
базы; синтетические данные в рабочую базу не добавляются.

Перед переходом локально сохранена отдельная копия
`.data/migration-before-node.sqlite3`. Исходники Python-версии доступны в коммите
`b7d696c`. Для возврата сначала остановите Node.js; не запускайте два разных
сборщика с одной базой одновременно.

Локальный бэкап не защищает от поломки диска: для длительного хранения копируйте
его на другое устройство или в своё хранилище.

## Telegram-бот

Бот запускается вместе с приложением, если заданы переменные окружения:

```text
PRICE_CHECKER_TELEGRAM_TOKEN_FILE=/var/lib/price-checker/secrets/telegram-bot-token
PRICE_CHECKER_TELEGRAM_OWNER_ID=123456789
PRICE_CHECKER_TELEGRAM_PROXY=http://127.0.0.1:17890
PRICE_CHECKER_PUBLIC_ORIGIN=https://<адрес-сайта>
```

Укажите свой числовой Telegram ID. Токен храните в отдельном файле с правами
`600`, доступном пользователю приложения; не добавляйте его в Git. Прокси
необязателен и применяется только к запросам Telegram. Запросы Randewoo сохраняют
свой маршрут. Без переменных Telegram локальное приложение работает как прежде.
Ошибки конфигурации бота отмечаются событием `telegram_disabled`, не останавливая сборщик.

Сначала откройте своего бота в Telegram и отправьте `/start`. Команды принимаются
только от указанного владельца в его личном чате с ботом:

- `/check_randewoo` — проверить цены Randewoo; повторный запуск во время его проверки отклоняется.
- `/check_ozon` — собрать всё избранное Ozon и цены из страниц списка. Недоступные товары отдельно не запрашиваются, их прежние цены и даты сохраняются. Расписание команда не включает.
- `/check` — показать команды выбора магазина без запуска проверки.
- `/status` — ход проверок, ближайшие запуски и состояние подключения каждого магазина.
- `/help` — список команд.

После плановой проверки, запуска из приложения, Telegram или `--once` приходит
короткий отчёт с логотипом магазина, московским временем, отдельными количествами
снижений и повышений цен и кнопкой перехода на сайт. Конкретные товары и цены
в сообщении не перечисляются. У Randewoo учитываются цены на сайте и в корзине,
у Ozon — текущие цены из избранного. Эти команды не используют AI.

При отсутствии изменений приходит короткий успешный итог. Ошибки описываются
одной строкой; повторяющиеся одинаковые ошибки подавляются, восстановление
отмечается в первом успешном отчёте. При задержке отправки больше пяти минут
отчёт сохраняет время сбора и получает соответствующую отметку.
Шаблоны и ID логотипов: [формат сообщений Telegram](docs/telegram-message-format.md).
Кнопка отчёта открывает раздел магазина: Ozon — `/ozon` (избранное),
Randewoo — `/cart`. При потере входа Ozon кнопка ведёт на `/ozon/login`.

Отчёты помечены названием магазина. Отчёты Randewoo сохраняются в таблице `telegram_outbox`, Ozon — в отдельной `telegram_ozon_outbox` рабочей SQLite-базы; их номера проверок независимы.
При сетевом сбое бот повторяет отправку с задержкой и учитывает `retry_after`;
очередь переживает перезапуск. При первом включении старая история не рассылается.
После сбоя, когда Telegram принял сообщение, но ответ потерялся, возможна повторная
доставка. Полученные команды отмечаются перед выполнением, чтобы перезапуск не
повторил уже запущенный сбор; при аварии до запуска команду можно отправить заново.
Логи содержат только тип события и безопасный код ошибки, без токенов и переписки.

На VDS переменные можно подключить отдельным `EnvironmentFile` в службе приложения.
Не задавайте общий `HTTP_PROXY` всей службе: Telegram использует собственную переменную
`PRICE_CHECKER_TELEGRAM_PROXY`.

### Переписка с Codex

Для обычных текстовых сообщений добавьте две переменные:

```text
PRICE_CHECKER_CODEX_EXECUTABLE=/usr/local/bin/price-checker-codex
PRICE_CHECKER_CODEX_WORKSPACE=/opt/price-checker/repository
```

`EXECUTABLE` — абсолютный путь к Codex CLI или обёртке, которая подключает прокси
только для Codex. CLI должен быть установлен и авторизован от пользователя службы.
Текущая интеграция проверена с Codex CLI 0.163.0 и входом через ChatGPT.
`WORKSPACE` — отдельный Git-каталог исходников в ветке `develop` с upstream `origin/develop`.
Codex меняет код и делает commit/push только в этой ветке. Владелец переносит изменения
из `develop` в `main` только через pull request (merge request). Прямой push в `main`,
force push и удаление ветки запрещены, в том числе для владельца. Активное правило
GitHub `main — pull requests only` применяется к `refs/heads/main` без исключений
в bypass list; для слияния обязателен PR и минимум один approval от другого
GitHub-аккаунта с необходимыми правами. Автор PR не может одобрить свой PR.
Конфигурация хранится в
`.github/main-ruleset.json`; изменения файла применяются отдельно в настройках GitHub.
Push в `develop` запускает проверки без деплоя на продакшен.
Бот не начинает новый вход и не запрашивает ключи в Telegram.

Обычные сообщения владельца обрабатываются последовательно, до 10 ожидающих сообщений.
Команды `/check_randewoo`, `/check_ozon`, `/status` и отчёты сборщиков работают во время ожидания AI.
`/new` начинает отдельный диалог после доставки предыдущих ответов, сохраняя старую
переписку. Продолжение использует явный ID сессии через `codex exec resume`, а не
поиск последней сессии. Сессии CLI сохраняются в домашнем каталоге пользователя службы.

Таблицы `telegram_dialogues` и `telegram_ai_messages` сохраняют сообщения, ответы,
ID сессии и прогресс доставки в рабочей SQLite-базе. Длинный ответ делится на части;
после перезапуска отправка продолжается с последней подтверждённой части. Для ответа,
который Telegram принял без полученного подтверждения, возможна повторная доставка.
Срок хранения истории сейчас не ограничен; её содержат также резервные копии базы.

Ожидающие запросы переживают перезапуск. Прерванный запрос не повторяется автоматически:
бот сообщает об остановке, и сообщение можно отправить снова. Вызов Codex ограничен
45 минутами. Ошибки входа, лимита и запроса сообщаются без сырых ответов сервера.
В логах нет переписки; текст запроса передаётся CLI через stdin, без аргументов процесса.

Codex выполняет команды от root с `danger-full-access`, читает файлы и логи,
редактирует исходники и управляет службами по заданию владельца. Само приложение
остаётся пользователем `pricechecker` с прежними ограничениями systemd. Обёртка
передаёт stdin и JSONL через SSH на loopback; отдельный ключ может запускать только
серверный Codex. Авторизация CLI и старые диалоги сохраняются в прежнем `CODEX_HOME`.

После изменений Codex обязан применить `$safe-commit-auto`, сделать коммиты и push.
Launcher перед запуском и Stop-хук при завершении требуют ветку `develop` с upstream
`origin/develop`. Stop-хук проверяет чистоту дерева и получает актуальную удалённую
ветку, подтверждая, что она содержит локальный коммит. Если проверка не прошла, хук просит закончить
коммит/push. Повторный отказ не вызывает бесконечный цикл: launcher дополнительно
проверяет Git и не передаёт успешное завершение. Отчёты лежат приватно в
`/var/lib/price-checker-codex/git-checks/`. Хук ничего не коммитит самостоятельно.

Установка: сначала `sudo python3 scripts/setup-codex-server.py --prepare-key`,
затем добавить выведенный публичный ключ как writable deploy key только этого
репозитория. После этого `sudo python3 scripts/setup-codex-server.py` устанавливает
обёртки, хук, skill и Git-каталог в ветке `develop`, сохраняя прежние файлы в приватной
резервной копии. Уже существующий каталог должен быть чистым и отслеживать `origin/develop`;
при другой ветке установщик останавливается без её автоматической смены.
После установки перезапустить службу приложения. Секретные ключи в репозиторий
не входят. Изменения исходников на сервере развёртываются через обычный CI/CD.

### GitHub CLI и пользователь xman

`sudo bash scripts/setup-server-tools.sh` устанавливает `gh` из репозитория Ubuntu
и создаёт обычного Linux-пользователя `xman` с домашним каталогом `/home/xman`
и оболочкой `/bin/bash`. Повторный запуск сохраняет существующего пользователя.
Новый аккаунт создаётся с заблокированным паролем, без sudo и SSH-ключей;
подключение по SSH настраивается отдельно. `gh` доступен и пользователю `xman`.

Установка CLI не авторизует его в GitHub. Авторизация настраивается отдельно
для выбранного Linux-пользователя и отдельного GitHub-аккаунта или приложения.
Пользователь Linux `xman` сам по себе не создаёт аккаунт GitHub. Скрипт не переносит
ключи, сессии и настройки root, не меняет текущий запуск Codex и службы приложения.

## Проверки и обслуживание

```powershell
npm test
npm run check
```

Тесты используют временные базы и фикстуры, не обращаясь к реальному аккаунту.
Проверяются парсинг, пагинация, история и совместимость схемы, расписание,
авторизация, блокировка процессов, HTTP API, защита секретов и CSV.

Для настоящей разовой проверки остановите фоновое приложение и выполните:

```powershell
npm run collect
```

Повторный экземпляр блокируется. После аварийного завершения блокировка может
сохраняться до 10 секунд; подождите и повторите запуск. Незавершённая проверка
после перезапуска отмечается как прерванная и может быть повторена.

Диагностика без записи в рабочую базу:

```powershell
node scripts/probe-products.js https://randewoo.ru/product/alfred-dunhill-icon --output scratch/icon-node.json
node scripts/probe-cart.js --output scratch/cart-node.json
```

Логи фонового процесса: `.data/server.log`, `.data/server-error.log`.

## Структура

- `run.js` — запуск сервера, обработка остановки и блокировка экземпляра.
- `src/client.js` — HTTP-транспорт curl и разбор HTML через Cheerio.
- `src/database.js` — SQLite и совместимая схема данных.
- `src/service.js`, `src/time.js` — сбор, синхронизация списков и расписание.
- `src/web.js` — HTTP API и CSV.
- `src/telegram.js` — личные команды владельца, Telegram-транспорт и очередь отчётов.
- `src/codex-chat.js` — вызов Codex CLI, сохранение диалогов и очередь ответов.
- `frontend/src/` — React + TypeScript, маршрутизация, запросы и compound components.
- `frontend/src/components/ui/` — исходники компонентов shadcn/ui.
- `dist/` — локальная сборка Vite; не включается в Git, не использует CDN.
- `tests/` — тесты backend на встроенном `node:test`.
- `frontend/src/**/*.test.*` — Vitest и React Testing Library.
- `e2e/` — браузерные тесты Playwright на изолированном стенде.

Используется встроенный [node:sqlite](https://github.com/nodejs/node/blob/v24.14.1/doc/api/sqlite.md), который в проверенной Node.js 24.14.1
помечен как экспериментальный. Предупреждение в логах ожидаемо; API и совместимость
базы проверены тестами. npm-зависимости зафиксированы в `package-lock.json`.

## Lamoda

Раздел `/lamoda` отслеживает всё избранное через отдельный постоянный Chrome:
текущую и зачёркнутую цены, наличие, историю, графики и собственное расписание.
База, очередь Telegram и облачные снимки Lamoda независимы от остальных магазинов.
Автосбор изначально выключен. Подключение аккаунта, серверная установка,
измерение нагрузки и восстановление описаны в [инструкции Lamoda](docs/lamoda.md).
