# Скачать копии трёх баз из продакшена

Проектный скилл для Price Checker. Источник: `root@153.76.171.172`,
базы магазинов в `/var/lib/price-checker/data`.

При запуске без уточнения магазина скачай независимые снимки **всех трёх баз:
Randewoo, Ozon и Lamoda**. Сохрани их в `.data/prod-snapshots/<магазин>/`,
не заменяя локальные рабочие базы. Если пользователь явно выбрал один магазин,
скачай только его базу. Обновление рабочей локальной базы Randewoo — отдельный
режим ниже, только по явному запросу пользователя.

## Запуск по умолчанию: все три базы

Из корня проекта выполни последовательно:

```powershell
node scripts/download-prod-db.mjs randewoo
node scripts/download-prod-db.mjs ozon
node scripts/download-prod-db.mjs lamoda
```

Каждая команда создаёт согласованный снимок выбранной базы через SQLite Backup
API на сервере, скачивает его, проверяет целостность и схему магазина, затем
сохраняет копию и JSON-метаданные в отдельный каталог магазина. Предыдущие копии
не перезаписываются. Не копируй сырой файл работающей SQLite-базы через `scp`:
незаписанные в основной файл изменения могут находиться в WAL.

Для скачивания снимков останавливать локальное приложение не требуется.
При ошибке одного магазина сохрани уже полученные копии и выполни команды
остальных магазинов. В отчёте явно укажи, какие базы скачаны, а какие нет;
не объявляй копирование всех трёх успешным, если хотя бы одна не получена.

## Дополнительно: обновить рабочую локальную базу Randewoo

Только если пользователь явно поручил заменить локальную рабочую базу Randewoo
данными с продакшена, выполни:

```powershell
node .agents/skills/price-checker-sync-prod-db/scripts/sync-prod-db.mjs
```

Этот режим скачивает снимок Randewoo в `.data/prod-snapshots/`, сохраняет прежнюю
локальную базу в `.data/local-backups/before-prod-sync-*.sqlite3` и обновляет
`.data/prices.sqlite3` через SQLite Backup API. Он не синхронизирует рабочие
локальные базы Ozon и Lamoda.

Если локальное приложение работает, скрипт завершится до скачивания данных.
В Windows останови только локальный экземпляр через `./stop.ps1`, повтори
синхронизацию и после успеха запусти его через `./start.ps1 -NoBrowser`, если
он работал до операции. Запомни нестандартный порт из `.data/server.json`;
`start.ps1` рассчитан на 8000, поэтому иной порт восстанови через
`node run.js --no-browser --port <порт>` обычным для этой сессии способом.
Не выводи содержимое `server.json`: в нём есть служебный токен.
При ошибке остановки не заменяй базу и не завершай неизвестные процессы.
Если синхронизация прервалась, сохрани исходную ошибку и восстанови ранее
работавший локальный экземпляр, когда база не повреждена.

## Подключение

Для подключения нужен обычный административный SSH-доступ, уже настроенный
на этом компьютере. Ключ `.secrets/github-actions-deploy` ограничен деплоем
и для чтения базы не подходит. Скрипт требует проверенный ключ хоста и
неинтерактивную авторизацию. Если SSH не работает, сообщи конкретную ошибку;
не отключай проверку ключа хоста и не запрашивай приватные ключи в чате.
Параметры `--host user@host`, `--port N`, `--identity путь` меняй только по
явному указанию пользователя.

## Результат и границы

- Для каждого магазина покажи путь сохранённого снимка, число наблюдений
  и время последнего наблюдения из JSON-результата команды. Для явного режима
  обновления Randewoo также покажи пути рабочей базы и её прежней копии.
- На сервере выполняется только чтение рабочей базы и создание временного
  снимка. Не останавливай продакшен, не запускай проверку цен и не меняй
  его базу, службу, конфигурацию или секреты.
- Копируются полные SQLite-базы, включая историю проверок и таблицы Telegram,
  если они есть. Cookies, файлы `.secrets` и системная конфигурация не копируются.
- Снимки и резервные копии находятся в игнорируемой `.data/`; не добавляй их
  в Git, не публикуй и не выводи содержимое диалогов в отчёт.
- После копирования базы независимы: последующие локальные изменения
  не отправляются в продакшен.
