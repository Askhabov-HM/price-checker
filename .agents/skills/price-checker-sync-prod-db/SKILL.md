# Обновить локальную базу из продакшена

Проектный скилл для Price Checker. Источник: `root@153.76.171.172`,
`/var/lib/price-checker/data/prices.sqlite3`. Назначение: `.data/prices.sqlite3`
в корне этого проекта. При запуске скилла пользователь поручает обновить эту
локальную базу с сохранением её прежней версии.

## Запуск

Из корня проекта:

```powershell
node .agents/skills/price-checker-sync-prod-db/scripts/sync-prod-db.mjs
```

Скрипт получает свежую копию через SQLite Backup API на сервере, скачивает её
в `.data/prod-snapshots/`, проверяет целостность и таблицы приложения. Затем
сохраняет прежнюю локальную базу в `.data/local-backups/before-prod-sync-*.sqlite3`
и обновляет рабочую базу через SQLite Backup API. Не копировать сырой файл
работающей SQLite-базы через `scp`: незаписанные в основной файл изменения
могут находиться в WAL.

Если локальное приложение работает, скрипт завершится до скачивания данных.
В Windows останови только локальный экземпляр через `./stop.ps1`, повтори
синхронизацию и после успеха запусти его через `./start.ps1 -NoBrowser`, если
он работал до операции. Запомни нестандартный порт из `.data/server.json`;
`start.ps1` рассчитан на 8000, поэтому иной порт восстанови через
`node run.js --no-browser --port <порт>` обычным для этой сессии способом.
Не выводи содержимое `server.json`: в нём есть служебный токен.
При ошибке остановки не заменяй базу и не завершай неизвестные процессы.
Если синхронизация прервалась, сохрани исходную ошибку и восстанови ранее
работавший локальный экземпляр, когда база не повреждена.

Чтобы только проверить получение свежих данных, без замены рабочей базы:

```powershell
node .agents/skills/price-checker-sync-prod-db/scripts/sync-prod-db.mjs --snapshot-only
```

Для независимого скачивания согласованной копии одного магазина без замены
локальных рабочих баз:

```powershell
node scripts/download-prod-db.mjs randewoo
node scripts/download-prod-db.mjs ozon
node scripts/download-prod-db.mjs lamoda
```

Каждая команда читает только выбранную серверную SQLite-базу через Backup API,
проверяет целостность и схему магазина, затем сохраняет копию и метаданные в
`.data/prod-snapshots/<магазин>/`. Неудачная загрузка оставляет ранее полученные
копии и локальные рабочие базы без изменений. Для нового просмотра запусти
нужную команду ещё раз; предыдущие копии не перезаписываются.

Для подключения нужен обычный административный SSH-доступ, уже настроенный
на этом компьютере. Ключ `.secrets/github-actions-deploy` ограничен деплоем
и для чтения базы не подходит. Скрипт требует проверенный ключ хоста и
неинтерактивную авторизацию. Если SSH не работает, сообщи конкретную ошибку;
не отключай проверку ключа хоста и не запрашивай приватные ключи в чате.
Параметры `--host user@host`, `--port N`, `--identity путь` меняй только по
явному указанию пользователя.

## Результат и границы

- Покажи пути обновлённой базы, резервной копии и снимка, число наблюдений
  и время последнего наблюдения из JSON-результата скрипта.
- На сервере выполняется только чтение рабочей базы и создание временного
  снимка. Не останавливай продакшен, не запускай проверку цен и не меняй
  его базу, службу, конфигурацию или секреты.
- Копируется вся SQLite-база, включая историю проверок и таблицы Telegram,
  если они есть. Файлы `.secrets`, настройки входа и сессия Randewoo не копируются.
- Снимки и резервные копии находятся в игнорируемой `.data/`; не добавляй их
  в Git, не публикуй и не выводи содержимое диалогов в отчёт.
- После синхронизации базы независимы: последующие локальные изменения
  не отправляются в продакшен.
