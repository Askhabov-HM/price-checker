# Правила работы ИИ с проектом

## Текущая задача Ozon

Расписания Randewoo и Ozon независимы и хранятся отдельно. Для каждого магазина выбирается ровно один режим: отмеченные часы по Москве (00:00–23:00; 24:00 означает 00:00) либо интервал 2, 30, 60 или 120 минут. Изменение режима, времени или включения одного магазина не должно менять настройки другого. Существующие настройки сохранять при обновлениях; исходный интервал Ozon — 30 минут.

Собирать всё избранное аккаунта и цены прямо из ответа избранного, без обхода карточек. Проходить пагинацию до конца. Нужны текущая цена (`PRICE`) и зачёркнутая (`ORIGINAL_PRICE`); неизвестные значения без сохранённой истории оставлять `null`.

Отсутствие товара в наличии не исключает его из слежения. При каждом общем сборе читать всё избранное и обновлять доступность, включая ранее недоступные товары. Пока товара нет в наличии, сохранять последнюю известную цену и исходную дату её получения; если истории нет, оставлять `null`. Сохранённую цену не выдавать за свежую. После возвращения товара автоматически сохранять свежие цены из избранного и сравнивать их с последней известной ценой, включая историю до возвращения. Повторное получение той же цены не сбрасывает последнее изменение. Для слежения использовать общий ответ избранного, без отдельных запросов карточек и поисковых перенаправлений. Недоступность отмечать синим в таблицах, истории и точках графиков; ошибки сбора отмечать красным.

Адрес, город и регион доставки не являются приоритетом или условием успешного сбора. Не тратить время на их настройку и проверку. Общий сбор не должен зависеть от корзины или товаров из наблюдения. Вход в нужный аккаунт проверять; при HTTP 403 получать данные через браузер.

При подтверждённой потере входа уведомлять владельца через существующего Telegram-бота со ссылкой на защищённую страницу `/ozon/login`. Номер брать из приватного `.secrets/ozon/login.json`, не переносить его в исходники или сообщения. Владелец сам вводит код в серверном окне Ozon; после подтверждения аккаунта сохранять cookies и закрывать браузер.

Временная ошибка сбора, включая HTTP 403, не выключает расписание и не требует ручного снятия паузы. При временных ошибках чтения выполнять до трёх повторов после первой попытки, удерживая общую очередь; после исчерпания попыток следующий сбор выполняется в следующий плановый срок. Явный `Retry-After` источника соблюдать, без немедленных повторов Ozon/Lamoda во время паузы. Подтверждённая потеря входа или другой аккаунт по-прежнему требуют действий владельца. Повторы не продлевают общий десятиминутный срок Android-задания Lamoda.

## Узлы VPN Ozon на сервере

Все узлы подписок UN1 и WASP доступны через `python3 /opt/price-checker/repository/scripts/ozon-vpn.py`. Команда `list` показывает безопасный список без ключей и текущий адрес основного прокси; `list un1` и `list wasp` фильтруют подписку. `refresh` обновляет обе подписки, а `refresh un1` или `refresh wasp` — одну. Подписки и полный каталог находятся только в приватных `/etc/price-checker-ozon-proxy/subscriptions.json` и `catalog.json`; их содержимое не печатать и в Git не добавлять. Подробности — `docs/ozon-vpn-nodes.md`.

Владелец может выбрать любой узел по подписке и номеру (`un1:2`, `wasp:8`) или постоянному ID из списка. Перед переключением получить свежий список; при обновлении подписки номера могут измениться, ID привязан к параметрам подключения. Для проверки использовать `check NODE`: только нейтральные HTTPS-запросы для определения внешнего IP и страны через временный прокси, без запросов к Ozon и Lamoda. Такая проверка не меняет активный маршрут и не запускает сбор.

Переключать только по запросу владельца командой `switch NODE`: она сначала проверяет узел, затем применяет его существующим установщиком под блокировками Ozon и общей очереди с откатом при ошибке. Доступны и страны вне Казахстана; страна выхода проверяется перед применением и повторно после него. Маршруты Lamoda, Randewoo, Telegram, расписания и вход владельца не менять. Автоматический выбор узла и автоматическое переключение не включать без отдельного запроса. Основным остаётся `95.56.251.12`, пока владелец не попросит другой узел.

## Ветка для Codex

Codex во всех средах изменяет проект, создаёт коммиты и отправляет их только в ветке `develop` с upstream `origin/develop`. Перед изменениями проверять текущую ветку и состояние Git. При другой ветке перейти в существующую `develop` только при чистом дереве и отсутствии незавершённых Git-операций; иначе остановиться и сообщить причину. Не создавать другие ветки или worktree для обхода ограничения.

Codex не делает коммиты, push или слияния в `main` и не отправляет изменения в другие удалённые ветки. Ветка `main` изменяется только через merge request (на GitHub — pull request), включая изменения владельца. Прямой push в `main`, force push, удаление ветки и обход защиты запрещены. Владелец переносит изменения из `develop` в `main` через pull request; локальное слияние с последующим push не допускается. Обязательные approvals отключены (0); владелец проверяет изменения и успешное завершение CI перед слиянием своего PR. CI проверяет обе ветки; автоматический деплой разрешён только из `main`.

Серверный launcher проверяет `develop` и upstream `origin/develop` до запуска Codex; завершающий хук повторяет проверку. Установщик интеграции должен создавать или принимать рабочий Git-каталог только с этой веткой и upstream.

## Серверный Codex и отправка изменений

Серверному Codex разрешены полный доступ к файлам, чтение логов, редактирование кода и конфигурации, управление службами и выполнение команд от root в рамках поручения владельца. Основной Git-каталог на сервере — `/opt/price-checker/repository`; рабочий релиз — `/opt/price-checker/current`. Исходники менять в Git-каталоге, а затем развёртывать сохранённую версию. Изменения системной конфигурации также отражать установщиками или шаблонами в репозитории. Секреты, базы, логи и приватные профили в Git не добавлять.

Если Codex изменил код, конфигурацию или правила проекта, до завершения задачи он обязан применить `$safe-commit-auto` (`.agents/skills/safe-commit-auto/SKILL.md`): проверить свои изменения, сделать логические коммиты и отправить их в upstream. Доступ не является разрешением на чужие изменения, force push или переписывание истории. Перед редактированием проверить состояние Git; при посторонних изменениях не включать их в свой коммит. Задачи без изменений не требуют пустого коммита. Явное указание владельца не коммитить или не отправлять имеет приоритет; в таком случае сообщить, что изменения не отправлены.

Завершающий хук проверяет ветку `develop`, upstream `origin/develop`, чистоту рабочего дерева и фактическое наличие локального коммита в удалённой ветке. Непроверенный или неотправленный результат не объявлять завершённым. При отклонённом push, отсутствии доступа или конфликте остановиться и сообщить причину; не обходить хук и не чинить историю автоматически.

## Тесты

Unit-тесты, проверки Python, сборку и статические проверки можно изменять и запускать без отдельного согласования. **Запуск e2e и браузерных тестов запрещён**, в том числе косвенно через скрипты, Git-хуки и CI/CD. Не запускать Playwright, Selenium и тестовые сценарии с реальным браузером. Модульные тесты с имитацией HTTP/CDP без запуска браузера разрешены. Перед составной командой или push учитывать её автоматические проверки. Не обходить запрет переименованием тестов.
