# Lamoda Collector для Android

Отдельное приложение для личного телефона владельца Price Checker. Android 8.0+
с обновлённым Android System WebView.
Встроенный WebView хранит вход Lamoda на телефоне. Приложение получает задание
VPS через push или проверку WorkManager, либо по кнопке «Собрать сейчас»:
читает все страницы избранного и отправляет только поля товаров и подтверждение
аккаунта. Сервер проверяет весь список перед сохранением цен в базу Lamoda.

Каждая страница избранного заново загружается в самом WebView без использования
кэша. Приложение ждёт завершения штатной проверки сайта, затем читает JSON из
документа этой страницы. Дополнительного `fetch` избранного нет: он мог получать
страницу проверки Servicepipe вместо товаров при сохранённом входе в окне.
При необходимости ручной проверки откройте приложение и завершите её на сайте.
Чтение одной страницы ограничено 75 секундами вместе с перенаправлениями;
общий десятиминутный срок задания не продлевается. URL и номер страницы в данных
должны соответствовать запрошенным; прежний документ повторно не используется.
Остановка отменяет загрузку и исключает запоздавшие результаты WebView.

## Установить APK

1. Возьмите `app/build/outputs/apk/debug/app-debug.apk` из этой папки. Также APK
   доступен в ZIP-артефакте `lamoda-collector-debug` успешного GitHub Actions.
2. Передайте APK на телефон по USB или отправьте себе в Telegram как файл.
3. Откройте APK на телефоне. При запросе Android разрешите установку из этого
   источника для приложения, которым открываете файл, и нажмите «Установить».
4. Запустите **Lamoda Collector**. Root, SMS, контакты, Accessibility и USB-отладка
   для работы не нужны.

Это debug-сборка для личной проверки. Для обновления без удаления нужна та же
подпись APK. Локальная и CI-сборка могут иметь разные debug-подписи; у CI подпись
может меняться и между запусками. Для обновлений без переустановки используйте
локальные сборки на одном ПК с сохранённым debug-ключом. Удаление приложения
удаляет сохранённый вход и токен телефона.

## Подключить сервер

Серверная часть соответствующего PR должна попасть в `main` и пройти деплой.
До этого WebView открывается, но подключение по новой ссылке недоступно.

1. В личном Telegram-боте Price Checker выберите **Подключить телефон для Lamoda**
   (`/lamoda_android`). Бот выдаёт эту ссылку только владельцу в личном чате.
2. На телефоне нажмите **Подключить телефон**, затем кнопку запуска приложения.
   Если Telegram блокирует переход, выберите в меню **Открыть в браузере**.
   Код и адрес вручную вводить не нужно. Ссылка одноразовая, действует 10 минут
   и заменяет прежнее подключение телефона; не пересылайте её.
3. Альтернатива: откройте на телефоне `https://153.76.171.172/lamoda/android`,
   войдите в Price Checker и нажмите **Подготовить подключение → Подключить этот Android**.
4. Войдите в аккаунт Lamoda внутри приложения. Это отдельный вход от Chrome
   и встроенного браузера Telegram.
5. После входа или прохождения проверки Lamoda нажмите **Собрать сейчас**.
   Окно можно свернуть или смахнуть из последних: сбором управляет WorkManager,
   WebView принадлежит процессу приложения, а не окну. Результат придёт через бота.
   Вход сохраняется между запусками и обновлениями APK с той же подписью;
   повторный вход нужен, если Lamoda завершит сессию. SMS-код при входе,
   если его требует сама Lamoda, вводится только на странице Lamoda.
6. После первого успешного сбора включите расписание в разделе Lamoda на VPS.
   Push ставит ускоренное задание в очередь без открытия окна; во время сбора
   Android показывает постоянное уведомление и удерживает foreground service.
   После завершения сбора уведомление исчезает. Дополнительно WorkManager
   проверяет ожидающее задание каждые 15 минут. Фоновая проверка и открытие
   приложения не создают ручных сборов вне расписания. Кнопка **Собрать сейчас**
   запускает ручной сбор. Расписания остальных магазинов не меняются.
7. До начала работы доступна **Отменить ожидание**, во время работы —
   **Остановить сбор**. Отменяется один запуск; неполный результат не меняет историю.
   Если запрос уже ушёл на VPS, приложение сохраняет отмену и ждёт подтверждения,
   в том числе после потери сети и перезапуска. При опоздавшей отмене VPS сообщает,
   что результат уже сохранён. Расписание и подключение не отключаются.

Подключение переключает только сбор Lamoda на телефон. Расписания остальных
магазинов не меняются. Отключение телефона на сайте отзывает токен и отменяет
текущий сбор. После отключения возвращается прежний серверный транспорт Lamoda;
для полной остановки проверок выключите также её расписание.

Включить на VPS сбор Lamoda каждые 30 минут можно в её настройках на сайте или
административной командой после деплоя соответствующего PR:

```sh
cd /opt/price-checker/current
sudo -u pricechecker node scripts/lamoda-schedule.js --root /opt/price-checker/current --apply
```

Без `--apply` команда показывает текущее состояние. Она использует проверки
аккаунта и расчёт расписания приложения, соблюдает `Retry-After` и сохраняет
якорь уже включённого интервала. Повтор не откладывает назначенный сбор.
Настройки находятся в базе Lamoda; обновление кода само по себе их не включает.
После первого включения новый интервал начинается через 30 минут; точное
`next_check` выводится в UTC. Окно приложения можно свернуть или смахнуть из
последних после входа и первого открытия обновлённого APK. Принудительную
остановку через настройки Android использовать нельзя: фон возобновится только
после следующего открытия приложения.

## Диагностика и отмена

Кнопка **Диагностика** показывает текущее состояние Android, очередь доставки и
последние 80 событий UTC. Отчёт можно скопировать или отправить через системное
меню **Поделиться**. Структурированный журнал хранится в приватной SQLite телефона,
работает без интернета и переживает перезапуск процесса. Лимит — 5000 событий или
5 МиБ текста; при переполнении удаляются старейшие записи, число потерянных
неотправленных событий видно в отчёте и последующих событиях на VPS.

WorkManager доставляет до 50 событий одним запросом; только подтверждённые VPS
записи снимаются с отправки. Независимая периодическая доставка выполняется
каждые 15 минут, даже когда сбор выключен. Повторная передача не создаёт дубликатов.
VPS хранит до 10000 событий телефона за последние 14 дней. На `/lamoda/android`
есть фильтр по заданию и единая шкала событий телефона и сервера: время события
и время получения VPS показаны отдельно, в часовом поясе Москвы.

Журнал содержит получение push, состояния/попытки WorkManager, условия сети и
батареи, запуск процесса, предыдущие завершения через ApplicationExitInfo
(Android 11+), HTTP-коды и длительности запросов, номера запусков/заданий/страниц.
Во время сбора отметка активности создаётся раз в 30 секунд. Пассивная отметка
«процесс жив» раз в минуту не удерживает процесс и не будит устройство.
Doze может задерживать и сами отметки, и их доставку. Старая доставленная запись
не считается свежим подтверждением работы. Отсутствие связи не доказывает гибель
процесса. Принятие push Firebase не доказывает получение сообщения телефоном.

Токены, cookies, коды/ссылки подключения, документы Lamoda и тексты исключений
не допускаются в новый журнал: поля проверяются на телефоне и VPS по белому списку.
Исходный журнал прежней сборки в SharedPreferences остаётся локально и не
отправляется. В debug-сборке новые события видны через
`adb logcat -d -s LamodaCollector:I '*:S'`; база — `databases/collector-state.db`.
Не копируйте целиком каталог приложения: в других его файлах есть приватные данные.

Ошибки источника содержат `source_reason`, HTTP-статус и номер страницы/задания.
Отдельно различаются ошибка загрузки, тайм-аут, отсутствие/неоднозначность блока
`__NUXT__`, ошибки разбора аккаунта и избранного. Перенаправления штатной проверки
обрабатывает WebView в пределах HTTPS-адресов Lamoda и исходного срока чтения.
Отсутствующий блок данных не доказывает ни капчу, ни потерю входа; только явный
`customer=null` означает подтверждённое отсутствие входа. Причина показывается
также в строке состояния приложения. Поле принимает только фиксированные коды,
тело ответа и адрес перенаправления не сохраняются. Сначала обновите VPS после
слияния PR, затем APK: прежний VPS не принимает новые поля диагностики.

Каждый запуск получает постоянный ID до отправки запроса. Повтор `/start` с тем
же ID не создаёт новый сбор. Отмена до первого запроса убирает локальное ожидание;
после отправки запроса она подтверждается VPS по ID запуска, даже при потере
ответа `/start`. Если известен номер задания из push, отменяется именно оно.
Задержанная отмена не затрагивает следующий запуск. Уже сохранённые цены не
откатываются. Десятиминутный срок задания не продлевается диагностикой и повторами.

Новая сборка требует мобильный протокол VPS 2. Сначала владелец сливает PR
`develop → main`, проходит штатный деплой с миграцией, затем обновляет APK с той
же подписью. На старом VPS приложение покажет требование обновления серверной
части и сохранит неотправленную диагностику. Старые APK совместимы с новым VPS.
Изменение APK или схемы не включает расписания. Вход, cookies и токен сохраняются.

## Ограничения

- WorkManager сохраняет периодическую проверку после перезагрузки и смахивания
  приложения. Doze, отсутствие сети и ограничения производителя могут задержать
  запуск. Принудительная остановка в настройках Android блокирует фон до следующего
  открытия приложения. Период 15 минут относится к проверке задания VPS, не к сбору
  Lamoda; его расписание остаётся на сервере. Один запуск ограничен 8 минутами,
  затем задача повторяется с последней подтверждённой страницы.
- Сервер хранит события Android-задания в отдельной таблице `mobile_diagnostics`
  базы Lamoda: создание, принятие push Firebase, обращение телефона, страницы и итог.
  На странице `/lamoda/android` показаны последние события. При обращении телефона
  фиксируется, заблокирован ли экран; при отсутствии ответа его состояние неизвестно.
  Принятие push Firebase не означает, что телефон получил или выполнил задание.
  Если телефон не обратился за заданием, сервер повторяет отправку того же push
  с двухминутной паузой, не более четырёх отправок и только до исходного срока задания.
- Длительный плановый сбор при заблокированном экране и удалении окна нужно
  проверить на конкретном телефоне. Сборка, JVM-тесты и lint этого не подтверждают.
- Капчу проходит владелец. Работа Lamoda в WebView ещё должна быть проверена
  на реальном телефоне. Парсер поддерживает наблюдавшийся формат `__NUXT__`;
  другая разметка вызывает ошибку без изменения сохранённых цен.
- Читается только `/wishlist/?page=N`, без обхода карточек, корзины и заказов.
  Перед автоматическим чтением следующей страницы выдерживается пауза 3 секунды
  после подтверждения передачи предыдущей страницы на VPS.
  Отправляются все страницы, максимум 1000. При изменении аккаунта или состава
  списка посреди сбора неполный результат не сохраняется.
- Для объединённых предложений Lamoda передаются `adjacent_skus` избранного и
  `hybrid_products` карточки. Сервер сопоставляет разные артикулы только при
  однозначной взаимной связи в этих полях. История сохраняется по исходному
  артикулу избранного; ссылка ведёт на карточку, из которой получена цена.
- На ожидание телефона и получение всех страниц отводится 10 минут с фактического
  запуска задания; время в общей очереди не учитывается. При перезапуске сервера проверка отменяется,
  повторный сбор начинается кнопкой **Собрать сейчас**. Повторная одинаковая
  отправка страницы допустима; ошибку сети можно повторить той же кнопкой. `Retry-After` соблюдается
  серверным планировщиком.
- Cookies Lamoda и пароль остаются в приватных данных приложения. Токен
  телефона зашифрован Android Keystore; на сервере хранится только SHA-256.
  Native JavaScript bridge не используется; токен недоступен странице Lamoda.
  Резервное копирование данных Android-приложения отключено.
- Для текущего сервера с собственным сертификатом сборка содержит его публичный
  SHA-256 в `app/build.gradle`. Проверка TLS не отключена. При смене сертификата
  обновите fingerprint и пересоберите APK. Другие серверы требуют обычный
  доверенный HTTPS-сертификат.

## Серверная часть

Код: `src/providers/lamoda/mobile.js`, API `/api/lamoda-mobile/*`, страница
`/lamoda/android`, существующие планировщик и Telegram-бот. Новые таблицы
находятся только в SQLite Lamoda и включаются в её существующие бэкапы.
Миграция добавляет таблицы без удаления истории.

Лимит страницы — 2 МиБ, нормализованных данных задания — 32 МиБ. Для Nginx на
текущем сервере выполните `sudo python3 /opt/price-checker/current/scripts/setup-lamoda-mobile.py`.
Установщик добавляет только мобильный маршрут, проверяет `nginx -t`, применяет
reload и сохраняет предыдущие файлы для восстановления. Остальные лимиты
остаются прежними. Исходный шаблон: `scripts/nginx/lamoda-mobile.conf`.
Без этого прежний общий лимит Nginx 100 КБ может отклонять большие страницы.
Bearer-токен телефона разрешает
только мобильный API; создание ссылки на сайте и отзыв требуют входа владельца
и CSRF, в Telegram — сообщения владельца в личном чате. Одноразовый секрет ссылки
передаётся в URL fragment, не попадает в HTTP query/access log и автоматически
обменивается приложением на токен. Адрес VPS не принимается из внешней ссылки.
У уже подключённого телефона токен сохраняется, повторная привязка не нужна.

## Push-напоминания Firebase

При запуске сбора по расписанию или с сайта VPS отправляет push. Приложение
проверяет актуальность задания и ставит фоновый сбор в очередь WorkManager.
Сообщение содержит только `data`: сочетание `notification` и `data` в фоне
Android показывается системой без вызова обработчика приложения. Уведомление
создаёт сам `ReminderService` после постановки фонового задания в очередь.
Уведомление позволяет открыть ход сбора и кнопку «Стоп». Приложение само
не открывается поверх других окон. При ручном запуске дополнительного push нет.
Разрешите уведомления при первом запуске обновлённого APK. Позже их можно
разрешить кнопкой **Разрешить уведомления** в приложении или в настройках Android.
Нужны интернет и Google Play services. При принудительной остановке приложения
через настройки Android откройте его снова, чтобы восстановить получение push.
Доставка через сеть Google может задерживаться; Telegram остаётся запасным
каналом. Успешный ответ FCM означает принятие сообщения, а не подтверждение
показа на телефоне. Без push ожидающее задание обнаруживает периодическая
проверка WorkManager; разрешение уведомлений не является условием этой проверки.

Настройка разработчиком/администратором один раз:

1. В Firebase добавьте Android-приложение с пакетом `ru.pricechecker.lamoda`.
   Скачанный `google-services.json` сохраните в корне репозитория в
   `.secrets/lamoda/google-services.json`. Файл с несколькими клиентами допустим:
   сборка выбирает именно пакет `ru`. Google Analytics подключать не нужно.
2. Включите Firebase Cloud Messaging API v1. Выдайте отдельному сервисному
   аккаунту роль `roles/firebasecloudmessaging.admin`, сохраните его JSON-ключ
   отдельно в `.secrets/lamoda/firebase-service-account.json`.
3. Для APK в GitHub Actions добавьте repository secret
   `LAMODA_FIREBASE_ANDROID_CONFIG` с содержимым клиентского `google-services.json`.
   Серверный ключ в этот secret и в APK не помещать. Для собственных веток CI
   требует настроенный secret; внешние PR собираются без Firebase и без публикации APK.
4. Скопируйте серверный ключ в приватный временный файл VPS, затем выполните:

   ```sh
   sudo python3 /opt/price-checker/current/scripts/setup-lamoda-push.py /private/service-account.json
   ```

   Установщик сохраняет ключ в `/var/lib/price-checker/secrets/lamoda/firebase-service-account.json`
   с владельцем `pricechecker` и правами `0600`, каталог — `0700`. Удалите временную
   копию. Следующий деплой приложения прочитает ключ через существующую ссылку
   `.secrets`; перезапуск старой версии не включает push.
5. После merge и деплоя обновите APK той же подписью и откройте приложение.
   Привязка телефона и cookies сохраняются. Токен FCM регистрируется на VPS
   автоматически, при смене токена повторяется в фоне с ожиданием доступной сети.

Push содержит только идентификатор сбора и срок действия, без cookies,
bearer-токена телефона, аккаунта Lamoda и списка товаров. Учётные данные Google
не попадают в Git. Сервер принимает регистрацию FCM только с токеном ранее
подключённого телефона; повторная привязка или отзыв удаляют старую регистрацию.
Очередь отправки хранится в SQLite Lamoda, повторяет временные ошибки с паузой
и `Retry-After`, пропускает истёкшие и отменённые сборы. Ошибка push не останавливает
сборщик или расписание. Поле `mobile.push.accepted_at` — время принятия FCM.

## Сборка

Нужны JDK 17+, Android SDK 36, Build Tools 35.0.0. SDK задаётся через
`ANDROID_HOME` или локальный `local.properties` с `sdk.dir` (не коммитится).

```powershell
cd apps/lamoda-android
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

Linux/macOS: `bash ./gradlew assembleDebug testDebugUnitTest lintDebug`.
Gradle 8.13 загружается wrapper-ом с проверкой опубликованного SHA-256.
CI выполняет сборку, JVM unit-тесты и lint. Эмуляторы, instrumentation,
e2e и тесты с реальным браузером не запускаются.
Без приватного клиентского JSON локальная сборка доступна для проверок и сбора,
но явно показывает, что уведомления Firebase не настроены.
