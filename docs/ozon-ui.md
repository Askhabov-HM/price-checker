# Раздел Ozon

18 октября 2026. Маршрут `/ozon`, отдельный пункт в навигации Price Checker.

## Доступные действия

- Добавить ссылку на любой конкретный вариант Ozon в наблюдение, убрать его без удаления истории.
- Обновить состав последних 30 обычных избранных и корзины, затем проверить объединение списков и наблюдения без повторов SKU.
- Проверить один выбранный товар отдельной кнопкой.
- Посмотреть обе цены, продавца, последнее время проверки, мини-графики товаров, обзорный график списка и подробную историю. Тип цены переключает все графики; в подробной истории можно менять период.
- Явно включить либо приостановить расписание каждые два часа. По умолчанию оно выключено; первое плановое чтение после включения отложено на два часа.

Состав списков заменяется только после подтверждения полноты обоих ответов. Рекомендации не попадают в избранное. Недоступные позиции сохраняются. Максимум 100 уникальных товаров за один проход; между карточками пауза 2,5 секунды, параллельных запросов нет. Для карточки используется сохранённая ссылка того же SKU, включая её slug, чтобы не вызывать лишнее перенаправление короткого адреса.

Обзор использует снимок состава и количества на момент каждой проверки и только цены этой проверки. В корзине учитывается количество, в избранном и наблюдении — одна единица. Смена SKU, количества, доступного состава или продавца прерывает линию. Неизвестная цена не становится нулём, ошибка не пополняет сумму прежней ценой. Неполная успешная проверка показывает подписанную сумму доступных товаров, ошибка — красную отметку. Старые проверки без сохранённого состава остаются в истории товаров; состав для них не восстанавливается из текущего списка. Мини-графики содержат последние 24 реальные проверки, подробная история сохраняет прежний период.

Обязательной двухчасовой паузы между ручными проверками нет. Два часа остаются только интервалом добровольно включаемого расписания. При 429 ожидание не менее шести часов с учётом `Retry-After`; явное ожидание источника сохраняется. При 401, отказе браузера, неподтверждённом контексте, неполных данных или прерванном процессе требуется восстановление подключения. Цена из ошибки не становится нулём и не заменяет последнюю успешную цену. После первого HTTP 403 без `Retry-After` текущий обход [переключается на серверный Chrome](ozon-recovery.md): карточки, избранное, корзина и условия Ozon Карты читаются в одном браузере, данные сохраняются с источником `browser`. Контрольных HTTP-повторов в этом обходе больше нет.

## Изоляция и безопасность

Ошибка отдельной карточки (перенаправление, некорректный ответ или отсутствие ответа) сохраняется в её истории и не обрывает оставшуюся очередь. Результат полного обхода с такими ошибками — `partial`; счётчик выполненных включает все попытки. Потеря входа, отказ доступа в браузере, 429, несовпадение аккаунта/доставки и явное ожидание источника останавливают очередь. В браузерном режиме HTTP-повторов нет. Прежняя цена остаётся в строке товара, но не включается в свежую сумму списка.

История Ozon находится в `.data/ozon/prices.sqlite3`, диагностика транспорта — в отдельном `probe.sqlite3`. База содержит собственную метку `ozon-prices` и версию схемы, неизвестная или чужая база отвергается до записи. Общих SQL-запросов с Randewoo нет. При ошибке открытия Ozon раздел сообщает о недоступности, Randewoo продолжает работать.

API находится под `/api/providers/ozon/`: `status`, `dashboard`, `product/ozon:item:<SKU>/history`, `watch/add`, `watch/remove`, `refresh`, `settings`. Публичные ID имеют префикс `ozon:item:`. Общие проверки входа, Origin и CSRF применяются ко всем новым операциям. При выходе из Price Checker кеш обоих магазинов очищается. В API нет cookies, ID аккаунта или точного адреса.

Приватные `.secrets/ozon/connection.json` и `session.json` содержат эталон аккаунта/доставки, разрешённые заголовки и scoped cookie jar. Импорт учитывает абсолютный срок cookies и только first-party partition `https://ozon.ru` без cross-site ancestor. Непрозрачная область и неоднозначные cookies отклоняются. Jar используется только для разрешённого API Ozon в этом контексте. Другая учётная запись или доставка не продолжает существующую персональную историю.

```text
npm run ozon:connect -- <private-request-and-reference.json> <private-browser-cookies.json>
npm run ozon:check -- https://www.ozon.ru/product/<SKU>/
npm run ozon:sync
```

Первая команда импортирует сессию без сети, снимает требование действий после обновления подключения, но не сокращает явное ожидание источника. Вторая — одна проверка выбранного товара с записью в БД и общей блокировкой сборщика. Третья — один полный импорт списков и проход цен; итог содержит только счётчики и безопасное сообщение. Ни одна команда не включает расписание. Прежние `ozon:probe`/`ozon:status` относятся только к самостоятельной диагностике транспорта и не отражают состояние нового раздела.

Перед деплоем резервируются существующие базы Randewoo и Ozon раздельно, через SQLite Backup API, с проверкой целостности и манифестом. Корневой SSH-загрузчик `/usr/local/lib/price-checker/deploy.py` устанавливается отдельно от релиза приложения. Служебное хранилище приложения из архитектурного проекта ещё не выделено; изменения не переносят текущие данные Randewoo и Telegram.

## Фактическая проверка одного товара

18 октября в 15:04 МСК один Node HTTP GET с сохранённой ночью сессией получил 403. Больше HTTP-повторов этой сессией не выполнялось, ошибка записана. Обход списков и других товаров не запускался.

Затем в сохранённом серверном Chrome открыта та же единственная карточка. Документ сначала получил 403, после штатной обработки страницей — 200; два явных браузерных GET карточки и её банков вернули JSON 200 в 15:07 МСК. Проверены аккаунт и доставка по приватному эталону, точный SKU, обычная и подтверждённая цена Ozon Карты, ID продавца. Успешное наблюдение записано с источником `browser`, первоначальный 403 оставлен в истории. Cookies обновлены из того же серверного профиля, Chrome и временная служба закрыты. Расписание осталось выключено.

Этот опыт показывает, что сохранённая HTTP-сессия не гарантирует бессрочный доступ без браузера. Позднее в тот же день автоматическое восстановление через Chrome реализовано и проверено на изолированной копии сервера; подробности в [отчёте восстановления](ozon-recovery.md). Длительная стабильность пока не подтверждена.

18 октября в 17:24 МСК выполнен свежий HTTP-импорт последних 30 избранных с `last_added` и трёх строк корзины. Аккаунт, доставка и полнота списков подтверждены; перед записью сохранена отдельная резервная копия БД Ozon. В очереди из 33 уникальных SKU первая карточка и условия Ozon Карты успешно прочитаны, следующая карточка вернула неподдерживаемое перенаправление. Очередь остановилась с сохранением списков, старых цен и паузы; расписание осталось выключено. Полная проверка цен всех товаров этим импортом не подтверждена.

Тесты без реального Ozon покрывают сохранность цен при ошибке, восстановление процесса, смену продавца, состав и количество для каждой точки суммы, пропущенные и недоступные цены, изоляцию БД, авторизацию и UI с общим графиком и мини-графиками.
