# Ozon: сравнение браузерного окружения

17 октября 2026. Отдельный worktree `price-checker-ozon-design`.

Обновление 18 октября: публичная карточка и аккаунтное чтение подтверждены непосредственно в новом профиле Chrome на Linux VDS после самостоятельного входа владельца. Немедленный перезапуск сохранил аккаунт, доставку и те же 30 избранных. Это дополняет первоначальное сравнение ниже и не позволяет объяснять прежний отказ одной ОС. См. [успешный Linux-эксперимент](ozon-public-product-linux.md).

## Подтверждённый результат

Windows Chrome на компьютере владельца, настроенный на временный SOCKS-туннель через VDS, открыл публичную главную Ozon с HTTP 200. Выходной IP этого браузера предварительно проверен: он совпадал с IP VDS. Первоначально пришла `Antibot Challenge Page` с 403, затем страница самостоятельно продолжила проверку и загрузила главную. Ручного обновления и входа в аккаунт не было.

Исходный Chrome на Ubuntu VDS в контрольной проверке того же периода остался на 403 и показал предложение выключить VPN/сменить сеть. Поэтому одного факта использования IP VDS недостаточно, чтобы объяснить все результаты. Различаются браузерное окружение, версия Chrome и состояние профиля; единственная причина ещё не выделена.

Позднее владелец вошёл в отдельный Windows-профиль с выходом через тот же VDS. Браузерное чтение избранного, корзины, карточки и её банков получило JSON 200; совпадение аккаунта и доставки подтверждено. Ниже описан первоначальный этап сравнения без входа. Результат последующего входа и его ограничения вынесены в [аккаунтную проверку](ozon-account-browser-check.md).

Последующий ограниченный запуск непосредственно на Linux VDS проверил `ru-RU`, рабочий WebGL через SwiftShader и cookies аккаунта. Избранное и выданная Ozon страница проверки завершились 403; наибольший зафиксированный пик памяти Chrome с Xvfb — около 427 МиБ, без OOM. Это не измерение полного сбора товаров. См. [отчёт Linux-проверки](ozon-linux-browser-check.md).

## Сравнение

Параметры измерены одинаковым JavaScript на собственной странице `127.0.0.1`. Она проверяла только возможности браузера и временные тестовые ключи своего origin. Существующие cookies, хранилища и содержимое других сайтов не читались. В таблице локальный основной профиль и новый контрольный профиль Windows разделены.

| Проверка | Основной локальный Chrome | Новый Windows Chrome через VDS | Исходный Chrome на VDS |
| --- | --- | --- | --- |
| ОС | Windows | Windows | Linux |
| Chrome | 155.0.8059.80 | 155.0.8059.80 | 155.0.8059.84 |
| `navigator.webdriver` | false | false | false |
| Язык | ru | ru-RU | en-US |
| Часовой пояс | Europe/Moscow | Europe/Moscow | Europe/Moscow |
| WebGL / WebGL2 | работают | работают | недоступны |
| Графика | аппаратная | аппаратная | Mesa/llvmpipe, Chrome блокирует WebGL |
| Canvas 2D | работает | работает | работает |
| Cookies / localStorage / sessionStorage / IndexedDB на тестовом origin | работают | работают | работают |
| Главная Ozon в этом эксперименте | не открывалась | 403 → автоматическая проверка → 200 | 403, страница сетевой ошибки |
| Вход в Ozon в контрольном профиле | не проверялся | не выполнялся | не выполнялся |

`webdriver` — [стандартное свойство браузера](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/webdriver). Из его значения false не следует, что Ozon не может учитывать другие признаки. Работа cookies на тестовом origin также не подтверждает вход в аккаунт Ozon.

В серверных логах зафиксированы `WebGL1 blocklisted` и `WebGL2 blocklisted`. Через CDP `SystemInfo.getInfo` подтверждён программный Mesa/llvmpipe и отключённый WebGL. Renderer при этом имел отдельные user/PID namespaces, seccomp и `NoNewPrivs`; отсутствие WebGL не означало отключённый sandbox renderer.

## Дополнительные ограниченные проверки

Выданная успешному Windows-браузеру `__Secure-ETC` с настоящими domain/path/expiry перенесена в приватную серверную HTTP-сессию. Остальные cookies авторизации остались из ранее захваченной локальной сессии владельца. Один прямой GET избранного 20:24 UTC вернул 403. Этой cookie оказалось недостаточно для переноса успешного браузерного доступа в Node. Авторизация, регион и состав избранного данным запросом не подтверждены; бан аккаунта из него не следует.

На отдельном новом серверном профиле проверен документированный режим программного драйвера `--use-gl=angle --use-angle=swiftshader`. WebGL/WebGL2 на нашей странице заработали. Однако CDP и `/proc` показали GPU-процесс без sandbox; sandbox renderer сохранился. Результат этого варианта ограничен собственной диагностической страницей, обращения к Ozon из него не выполнялись. Доступность WebGL не объявляется исправлением 403. Режимы SwiftShader и ограничения описаны в [документации Chromium](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md).

## Состояние после первоначального сравнения

Тестовые окна, службы браузера, MCP-подключения, локальная диагностическая страница и SSH-туннели остановлены. Отдельные профили и сырые отчёты сохранены приватно в `.secrets/` и изолированных серверных каталогах. Cookie-значения, IP и характеристики личного GPU в этот документ не включены.

Price Checker и Mihomo остались активны без перезапуска. Рабочие базы Randewoo не открывались. Расписание Ozon не включено; источник остаётся на паузе. Новые сведения не подтверждают автономный аккаунтный сбор на VDS: для него ещё нужны рабочий серверный браузерный профиль/транспорт, проверенная авторизация и доставка, а затем проверка с перезапуском и расписанием.
