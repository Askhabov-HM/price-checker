# Быстрое чтение таблиц и графиков

Изменения от 25 октября 2026 года. Исходная версия для сравнения и возврата:
`52d26df60ab1adc26a7a7855c4f3af06519b3378`.

## Что изменилось

### Готовые точки общего графика

Randewoo, Ozon и Lamoda сохраняют рассчитанные точки в `list_history_points`.
История Lamoda с ПК использует `desktop_history_points`. При чтении страницы
приложение выбирает готовые точки за нужный период. Оно больше не складывает
все наблюдения каждого сбора заново при каждом открытии страницы.

Первая загрузка заполняет историю из существующих наблюдений. Далее окончание
сбора обновляет его точки; `running` не считается окончательным результатом.
Статусы успеха, частичного результата, ошибки и прерывания учитываются.
Триггеры SQLite отмечают изменения источников: исправление или удаление
наблюдения пересчитывает соответствующий сбор, изменение исторического
членства Randewoo — затронутые списки. Следующее чтение также обрабатывает
незавершённое обновление кеша, например после перезапуска приложения.

Вместо полного перечня SKU в каждой точке API передаёт `composition` —
46-символьный SHA-256 ключ исходного состава. График по-прежнему разрывает
линию при смене состава, количества, продавца или набора известных цен
согласно правилам соответствующего магазина. Товары для самой таблицы
по-прежнему загружаются; повторять их состав внутри каждой точки не нужно.

### Статистика товаров

`price_rows` и `desktop_rows` содержат последнюю цену, статистику, последнее
изменение и последние 24 наблюдения для мини-графика. Первый расчёт читает
историю, следующие — только добавленные наблюдения. Исправления, удаления,
импорт с прежним ID или более ранней датой перестраивают данные затронутого
товара. Данные нескольких товаров запрашиваются пакетно.

Триггеры работают и при записи из другого соединения или прежней версии
приложения. SAVEPOINT связывает обновление вычисленных данных с исходной
транзакцией: её откат отменяет и обновление кеша. Исходные таблицы наблюдений
не заменяются и не очищаются. Будущие изменения алгоритмов расчёта должны
явно инвалидировать соответствующие кеши; одного изменения JavaScript
недостаточно для уже сохранённых результатов.

Для уведомлений Randewoo добавлены индексы
`observation_check(check_id,variant_id,context,id)` и
`observation_previous(variant_id,context,id DESC)`. Поиск текущей проверки
и предыдущих цен больше не требует полного просмотра таблицы и отдельной
сортировки. Текст и условия уведомлений сохранены.

### Обновление интерфейса

Во время сбора продолжают обновляться статус и прогресс. Запросы таблицы,
общего графика, мини-графиков и открытой истории товара приостановлены.
Уже полученные данные остаются на экране. Ответ начатого ранее запроса
отменяется, чтобы не показать промежуточный результат.

После любого окончания сбора данные обновляются. Окончание определяется
по ID, статусу и времени завершения; счётчик обработанных товаров не вызывает
перезагрузку цен. Для Lamoda с ПК учитываются ID успешного снимка и последней
ошибки. Это позволяет заметить и короткий сбор между двумя опросами статуса.

Если страница впервые открыта во время сбора и сохранённых данных ещё нет,
таблица и графики загружаются после окончания. Обычные изменения списков и
настроек вне сбора продолжают обновлять интерфейс.

### Прокрутка графика

Полноразмерные общие графики и история отдельного товара имеют горизонтальную
прокрутку снизу. Минимальная ширина зависит от числа точек; в режиме
«По проверкам» на шаг отводится примерно 20 пикселей. Режим «По времени»
сохраняет настоящие интервалы между датами. Шкала цены закреплена слева.

Начальное положение — справа, у последнего сбора. Новые точки продолжают
держать правый край, если пользователь находился там. Ручная прокрутка в
прошлое сохраняется при добавлении точек; смена масштаба или начала выбранной
истории открывает правый край снова. Мини-графики остаются компактными.

Сравнение выполнено локально на Windows, Node.js 24.14.1. Согласованные

новый код читали отдельные экземпляры одинаковых данных. Рабочая продовая
база этими экспериментами не изменялась.

## Автоматические проверки

- Сборка, TypeScript, проверки синтаксиса, backend unit-тесты и Python-тесты.
- Сохранение результата при повторном чтении, добавлении, исправлении,
  удалении, позднем импорте, перезапуске и записи из другого соединения.
- Откат транзакции, окончания с разными статусами, порядок одинаковых дат,
  границы состава и индексный план запроса Telegram.
- React Query в jsdom: остановка запросов во время сбора, отмена запоздалого
  ответа, загрузка после окончания, открытие страницы во время сбора.
- Реальный компонент Recharts в jsdom: линии и точки, начальная прокрутка
  вправо, сохранение ручной прокрутки, закреплённая шкала.

Браузерные и e2e-тесты не запускались по правилам проекта. Визуальная проверка
в настоящем браузере не проводилась. Сборка сохраняет предупреждение о
JS-бандле больше 500 кБ. Локальные снимки, скрипт сравнения и логи находятся
в игнорируемой `.data/performance-20261025/`, в Git их нет.

## Выпуск и откат

Изменения отправляются в `develop`. Выпуск выполняется владельцем через PR
`develop → main` после проверки CI. Сам push в `develop` не обновляет продакшен.

Коммиты реализации:

- `caab3f7` — кеши таблиц и графиков, компактный состав, индексы Randewoo.
- `c98d2ba` — обновление данных интерфейса после окончания сбора.
- `3520337` — горизонтальная прокрутка графиков.

Миграция добавляет таблицы, триггеры и индексы. Старые таблицы, история цен,
настройки и расписания сохраняются. Перед выпуском применяется обычная
процедура резервного копирования проекта.

Для возврата к прежнему поведению:

1. В чистой ветке `develop` отменить коммиты реализации обычным `git revert`
   в обратном порядке: прокрутка, обновление интерфейса, кеши/индексы.
   Имена и SHA доступны в истории Git; исходная точка указана в начале файла.
2. Проверить результат разрешёнными unit/static/build-проверками и отправить
   новые revert-коммиты в `origin/develop`.
3. Перенести откат через PR в `main` и обычный процесс выпуска.

Для этих трёх коммитов команда первого шага:

```sh
git revert 3520337 c98d2ba caab3f7
```

Если после них появились зависимые изменения или Git сообщил о конфликте,
откат требует отдельного разбора; продолжать автоматически не следует.

`revert` сохраняет исходные изменения и сам откат в истории. `reset`, force
push и восстановление старой копии БД для отката кода не нужны: последнее
потеряло бы цены, собранные после резервного копирования. Прежний код не
читает новые вычисленные таблицы; их можно оставить в базе. Триггеры при
этом продолжают отмечать новые записи для возможного возвращения новой
версии. Не следует вручную удалять таблицы кеша отдельно от их триггеров.

## Сохранённые ограничения

Общий сбой Ozon без записанных наблюдений по-прежнему может не давать точки
общего графика. Отдельная политика таких точек не входит в это изменение.
Существующие пределы истории отдельного товара (Ozon 2000, Lamoda 5000) и
лимит снимков/ошибок общего графика Lamoda с ПК (по 1000) сохранены.
