# Ozon: HTTP после входа непосредственно на Linux

18 октября 2026, 00:34–00:35 МСК. Отдельный worktree `price-checker-ozon-design`.

## Результат

На текущем VDS Node.js получил избранное, корзину, одну карточку и её условия банковской цены через прямой HTTP. Все четыре GET вернули JSON 200 без перенаправлений и повторов. Во время HTTP-проверок Chrome был закрыт; компьютер владельца для чтения не использовался.

| Чтение | Проверка содержимого |
| --- | --- |
| Избранное | Тот же аккаунт и выбранная доставка; последние 30 настоящих избранных, полный результат для лимита |
| Корзина | Тот же аккаунт/доставка; 3 строки, полнота подтверждена парсером |
| Одна карточка | Тот же аккаунт/доставка, точный SKU, обычная и банковская цена, числовой ID продавца |
| Условия оплаты этой карточки | Тот же SKU; цена Ozon Карты подтверждена вместе с карточкой |

Корзина, карточка и банки прочитаны вторым процессом Node после восстановления сохранённой HTTP-сессии. Повторного запуска Chrome или входа между этими HTTP-чтениями не было.

## Как получена сессия

Использован сохранённый серверный профиль из [успешной Linux-проверки](ozon-public-product-linux.md), в котором владелец самостоятельно вошёл и выбрал доставку. Chrome кратко запущен для экспорта cookies через CDP, затем штатно закрыт до первого HTTP-запроса. Удалённое окно и SSH-туннели для этого не запускались.

В диагностическую сессию импортированы 10 cookies с реальными domain/path, признаками Secure/HttpOnly, сроком истечения и областью действия. Заголовки User-Agent, Accept, Accept-Language и Referer взяты из успешного Linux Network-снимка. Заголовок Cookie собирался заново из свежего серверного экспорта; старые Windows cookies не использовались.

Одна cookie имеет partition key. В одноразовом тесте допущена только подтверждённая привязка к top-level `https://ozon.ru` без cross-site ancestor, для фиксированного чтения API того же сайта. Непрозрачная либо другая привязка не принимается. Исходные метаданные сохранены в приватном экспорте. Это ограниченный диагностический импорт: универсальный перенос браузерной сессии с сохранением partition-контекста в рабочий HTTP-сборщик ещё нужно реализовать.

Два подготовительных запуска остановились до сетевого запроса на проверке partition-контекста. После его проверки отправлены ровно четыре GET к Ozon. Обхода после 403 и автоматических повторов не было.

## Ресурсы и состояние сервера

Максимальный RSS процесса Node: около 113 МиБ при чтении избранного и 112 МиБ при чтении остальных данных. Это измерение диагностических процессов, а не гарантированный бюджет полного цикла. С прежним пиком cgroup браузера его нельзя сравнивать как одинаковые метрики.

После проверки Chrome и удалённое окно выключены, порты 9224/5904/6084 не слушают. На хосте доступно около 1318 МиБ RAM. Price Checker остался `active/running`, `NRestarts=0`. Рабочие базы и конфигурация Randewoo не менялись. Прежняя диагностическая пауза Ozon не сброшена; постоянное расписание не включено.

Сессия, полные ответы, заголовки и служебные отчёты находятся только в приватном каталоге отдельного стенда VDS. Аккаунт, точный адрес, значения cookies и выбранный SKU в этот документ не включены.

## Практический вывод

Постоянно работающий Chrome для проверенных чтений не потребовался. Теперь основной кандидат — HTTP-worker с отдельной БД Ozon, а сохранённый Chrome-профиль нужен для восстановления доступа или повторного входа, если они понадобятся.

Проверен короткий ручной сеанс, включая перезапуск Node. Срок жизни доступа без браузера, повтор через два часа, несколько последовательных циклов и полный проход по 30 карточкам ещё не проверены. Прежние 403 относились к другим состояниям сессии; какой именно фактор изменил результат, отдельно не установлен. Гарантировать отсутствие будущих отказов по этому опыту нельзя.

После эксперимента владелец приостановил дальнейшие проверки Ozon. Двухчасовой повтор и постоянное расписание отложены; сохранение кода в Git и обновление приложения на prod не возобновляют сбор.
