# Резервные копии БД в Google Drive

Служба `price-checker-backup.timer` раз в минуту проверяет завершённые сборы
и новые наблюдения Randewoo и Ozon. После изменений создаёт согласованные
снимки **обеих** SQLite через Backup API. При отсутствии изменений сохраняет
снимок не реже раза в час, включая изменения настроек и служебных таблиц.
Сборщики и веб-приложение продолжают работать. Данные магазинов сохраняются
отдельными файлами, каждый со своим согласованным моментом снимка.

`restic` шифрует содержимое и метаданные, сжимает и дедуплицирует данные.
`rclone` передаёт зашифрованный репозиторий в отдельную непубличную папку
`price-checker-backups` в выбранном Google Drive. Облачный пароль и токены
не входят в бэкап и никогда не сохраняются в Git.

В снимках находятся все таблицы рабочих БД, включая историю цен, настройки
и служебные данные Telegram, которые приложение хранит в SQLite. Входы в
магазины, cookies, системная конфигурация и другие файлы `.secrets` в этот
бэкап не входят. После потери сервера их потребуется настроить отдельно.

## Установка

Исходники находятся в `develop` с upstream `origin/develop`. Устанавливать
только сохранённую и отправленную версию из серверного Git-каталога
`/opt/price-checker/repository`; служба приложения и рабочий релиз не меняются.

```sh
bash scripts/setup-google-drive-backup.sh
```

Установщик добавляет `restic`, `rclone`, отдельные systemd units, конфигурацию
`/etc/price-checker-backup.json` и новый случайный пароль шифрования в
`/var/lib/price-checker/secrets/google-drive-backup/restic-password`.
Повторная установка сохраняет существующие настройки и пароль.
Без `--enable` новый таймер не запускается.

Один раз авторизовать rclone под выбранным владельцем Google Drive.
Использовать scope `drive.file`: доступ только к файлам/папкам, созданным
этим приложением. Подключение Google Drive в ChatGPT не передаёт авторизацию
серверу. Пароли, OAuth token и полное содержимое конфигурации не выводить.

Конфигурация rclone:

```ini
[pricechecker-drive]
type = drive
scope = drive.file
# token заполняется авторизацией Google, не копировать в документацию
use_trash = false
```

Файл `/var/lib/price-checker/secrets/google-drive-backup/rclone.conf` имеет
права 600. `use_trash=false` нужен для освобождения места при плановом удалении
устаревших блоков **выделенного репозитория бэкапов**; личные файлы не затрагиваются.

Создать новую папку через это же подключение и инициализировать репозиторий:

```sh
rclone --config /var/lib/price-checker/secrets/google-drive-backup/rclone.conf mkdir pricechecker-drive:price-checker-backups
python3 /usr/local/lib/price-checker/google-drive-backup.py init
```

Перед включением обязательно сохранить пароль `restic-password` вне сервера,
например в менеджере паролей владельца. Google Drive без этого пароля не
позволит расшифровать репозиторий. Отдельно записать Google-аккаунт и ссылку
на папку; OAuth можно выдать заново после потери сервера.

```sh
bash scripts/setup-google-drive-backup.sh --enable
```

`--enable` сначала выполняет полную отправку, проверку restic и восстановление
из Google Drive в отдельный временный каталог. Только после успеха включает
таймер. Восстановленные SQLite проходят `integrity_check`; SHA-256, размеры,
количества записей, крайние даты наблюдений и принадлежность магазину
сверяются с манифестом. Рабочие базы не заменяются.

## Хранение и контроль

- Все снимки за 48 часов, по одному за день за 30 дней и по одному за месяц
  за 12 месяцев. Это точки восстановления; каждый снимок содержит всю
  историю, которую рабочая БД хранила в момент его создания.
- Раз в сутки после нового бэкапа — скачивание, полное восстановление и
  сверка манифеста, затем очистка старых снимков и проверка репозитория.
- Сбой отправки/проверки не обновляет отметку успешного бэкапа; следующий
  запуск повторяет попытку. Расписания магазинов не меняются.
- Бэкап замечает новые данные примерно за минуту плюс время передачи.
  При потере серверной БД записи после последнего успешного бэкапа могут
  быть потеряны. Сбой облака может увеличить этот промежуток.
- Бесплатная квота Drive ограничена. Проверять свободное место в Google
  Drive и ошибки службы; для резервных копий не создавать публичные ссылки.

```sh
systemctl status price-checker-backup.timer price-checker-backup.service
journalctl -u price-checker-backup.service --since today
python3 /usr/local/lib/price-checker/google-drive-backup.py status
python3 /usr/local/lib/price-checker/google-drive-backup.py run --force
```

Рабочий каталог `/var/lib/price-checker-backup` содержит последнюю локальную
пару снимков, кэш restic и `state.json` с последней успешной отправкой,
проверкой восстановления и безопасным сообщением об ошибке. Это приватные
данные с правами 700/600.

## Восстановление

На новой машине установить restic/rclone, заново авторизовать **тот же
Google-аккаунт**, вернуть сохранённый пароль шифрования в приватный файл и
задать пути в конфигурации. При scope `drive.file` использовать тот же OAuth
клиент rclone; если доступ к прежним файлам не выдаётся, владелец может выдать
новую авторизацию со scope `drive` для восстановления своей папки.
Не выполнять `init` поверх существующего репозитория.

Узнать ID доступных снимков:

```sh
export RCLONE_CONFIG=/var/lib/price-checker/secrets/google-drive-backup/rclone.conf
export RESTIC_PASSWORD_FILE=/var/lib/price-checker/secrets/google-drive-backup/restic-password
restic -r rclone:pricechecker-drive:price-checker-backups snapshots
python3 /usr/local/lib/price-checker/google-drive-backup.py restore SNAPSHOT_ID --target /srv/price-checker-recovery
```

`SNAPSHOT_ID` заменить реальным ID из списка. Команда требует новый каталог,
проверяет обе базы и не позволяет восстановление поверх рабочих данных.
Файлы находятся в `staging/randewoo.sqlite3` и `staging/ozon.sqlite3`.
Заменять рабочие базы только отдельной операцией при остановленной службе,
после сохранения текущих файлов, проверки совместимости схемы с кодом и
с соблюдением владельца/прав. Старые WAL/SHM нельзя оставлять рядом с
восстановленными файлами. Восстанавливать магазин только из его файла.
