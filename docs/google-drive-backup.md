# Резервные копии БД в Google Drive

Три службы независимо резервируют базы магазинов:

| Магазин | Таймер | Состояние и локальный снимок |
| --- | --- | --- |
| Randewoo | `price-checker-store-backup@randewoo.timer` | `/var/lib/price-checker-randewoo-backup` |
| Ozon | `price-checker-store-backup@ozon.timer` | `/var/lib/price-checker-ozon-backup` |
| Lamoda | `price-checker-lamoda-backup.timer` | `/var/lib/price-checker-lamoda-backup` |

Randewoo/Ozon проверяют изменения через минуту после предыдущего запуска;
Lamoda — каждую минуту на 30-й секунде. Новый завершённый сбор, наблюдение
или изменение схемы вызывает копирование только соответствующей базы.
Без таких изменений копия создаётся при следующей проверке после истечения
часа с последнего успеха: это захватывает настройки и служебные таблицы.
При ошибках/ожидании очереди этот срок увеличивается; успешный бэкап не обещается
ровно через минуту или час. Повторные запуски одной службы не накапливаются.

Согласованный **полный** снимок SQLite создаётся через Backup API.
В облако restic передаёт отсутствующие блоки и метаданные, а не SQL-строки.
Каждый снимок восстанавливается как полная база. Локальные чтение/копирование
и проверка SHA-256 всё равно обрабатывают полный файл.

Все операции бэкапа, восстановления и обслуживания последовательно захватывают
`/var/lib/price-checker-backup-coordination/repository.lock`. Это отдельная от
сбора цен очередь, без гарантии FIFO. У каждой службы дополнительно свой
`backup.lock`: второй запуск того же магазина отклоняется. Ожидание общей
блокировки ограничено 40 минутами; внешние команды после допуска — общим
бюджетом 20 минут. systemd ограничивает весь запуск 65 минутами. Блокировки
освобождаются ОС после завершения процесса. Ошибка одного магазина не изменяет
состояние бэкапа другого и не меняет результат уже сохранённого сбора.

`restic` шифрует содержимое и метаданные, сжимает и дедуплицирует данные.
`rclone` передаёт зашифрованный репозиторий в отдельную непубличную папку
`price-checker-backups` в выбранном Google Drive. Облачный пароль и токены
не входят в бэкап и никогда не сохраняются в Git.

В снимках находятся все таблицы рабочих БД, включая историю цен, настройки
и служебные данные Telegram, которые приложение хранит в SQLite. Входы в
магазины, cookies, системная конфигурация и другие файлы `.secrets` в этот
бэкап не входят. После потери сервера их потребуется настроить отдельно.

## Установка

Исходники находятся в `develop` с upstream `origin/develop`. Устанавливать
только сохранённую и отправленную версию из серверного Git-каталога
`/opt/price-checker/repository`; служба приложения и рабочий релиз не меняются.

```sh
bash scripts/setup-google-drive-backup.sh
```

Установщик добавляет `restic`, `rclone`, отдельные systemd units, конфигурацию
`/etc/price-checker-backup.json` и новый случайный пароль шифрования в
`/var/lib/price-checker/secrets/google-drive-backup/restic-password`.
Повторная установка сохраняет существующие настройки и пароль.
Без `--enable` новый таймер не запускается.

Один раз авторизовать rclone под выбранным владельцем Google Drive.
Использовать scope `drive.file`: доступ только к файлам/папкам, созданным
этим приложением. Подключение Google Drive в ChatGPT не передаёт авторизацию
серверу. Пароли, OAuth token и полное содержимое конфигурации не выводить.

Конфигурация rclone:

```ini
[pricechecker-drive]
type = drive
scope = drive.file
# token заполняется авторизацией Google, не копировать в документацию
use_trash = false
```

Файл `/var/lib/price-checker/secrets/google-drive-backup/rclone.conf` имеет
права 600. `use_trash=false` нужен для освобождения места при плановом удалении
устаревших блоков **выделенного репозитория бэкапов**; личные файлы не затрагиваются.

Создать новую папку через это же подключение и инициализировать репозиторий:

```sh
rclone --config /var/lib/price-checker/secrets/google-drive-backup/rclone.conf mkdir pricechecker-drive:price-checker-backups
python3 /usr/local/lib/price-checker/google-drive-backup.py init
```

Перед включением обязательно сохранить пароль `restic-password` вне сервера,
например в менеджере паролей владельца. Google Drive без этого пароля не
позволит расшифровать репозиторий. Отдельно записать Google-аккаунт и ссылку
на папку; OAuth можно выдать заново после потери сервера.

```sh
bash scripts/setup-independent-backups.sh --enable
```

Установщик запускается из чистого, сохранённого и отправленного Git-каталога
`develop` с upstream `origin/develop`. Он приостанавливает таймеры, дожидается
текущих операций, сохраняет прежние инструменты и units для отката. Затем
выполняет отправку и восстановление **каждой из трёх баз** в отдельный временный
каталог, а также проверку/обслуживание restic. Только после успеха отключает
прежний объединённый таймер и включает три независимых таймера и обслуживание.
При ошибке возвращает прежние инструменты и состояния таймеров. Рабочее
приложение не останавливается; старые копии, секреты и настройки сохраняются.
Восстановленные SQLite проходят `integrity_check`; SHA-256, размеры,
количества записей, крайние даты наблюдений и принадлежность магазину
сверяются с манифестом. Рабочие базы не заменяются.

## Хранение и контроль

- Все снимки за 48 часов, по одному за день за 30 дней и по одному за месяц
  за 12 месяцев. Это точки восстановления; каждый снимок содержит всю
  историю, которую рабочая БД хранила в момент его создания.
- После первого бэкапа и далее примерно раз в сутки — скачивание, полное
  восстановление и сверка манифеста. Только после успеха магазин удаляет ссылки
  на свои устаревшие снимки, сохраняя как минимум последний. Метки:
  `price-checker-randewoo`, `price-checker-ozon`, `price-checker-lamoda`.
- `price-checker-backup-maintenance.timer` ежедневно в 05:15 по времени сервера
  выполняет `check`, `prune`, `check` под общей блокировкой. Он не удаляет снимки
  (`forget`); ошибки обслуживания сохраняются отдельно. Старые объединённые
  снимки с меткой `price-checker-databases` автоматически не удаляются.
- Сбой отправки/проверки не обновляет отметку успешного бэкапа; следующий
  запуск повторяет попытку. Расписания магазинов не меняются.
- Бэкап замечает новые данные примерно за минуту плюс время передачи.
  При потере серверной БД записи после последнего успешного бэкапа могут
  быть потеряны. Сбой облака может увеличить этот промежуток.
- Бесплатная квота Drive ограничена. Проверять свободное место в Google
  Drive и ошибки службы; для резервных копий не создавать публичные ссылки.

```sh
systemctl status price-checker-store-backup@randewoo.timer price-checker-store-backup@ozon.timer price-checker-lamoda-backup.timer price-checker-backup-maintenance.timer
journalctl -u price-checker-store-backup@randewoo.service --since today
python3 /usr/local/lib/price-checker/store-backup.py --store randewoo status
python3 /usr/local/lib/price-checker/store-backup.py --store ozon run --force
python3 /usr/local/lib/price-checker/lamoda-backup.py status
python3 /usr/local/lib/price-checker/backup-maintenance.py status
```

В каждом каталоге магазина находятся локальный снимок, кэш restic и `state.json`
с последней успешной отправкой, проверкой восстановления и безопасной ошибкой.
Обслуживание использует `/var/lib/price-checker-backup-maintenance`.
Прежний `/var/lib/price-checker-backup` сохраняется для старых снимков.
Это приватные данные с правами 700/600.

## Восстановление

На новой машине установить restic/rclone, заново авторизовать **тот же
Google-аккаунт**, вернуть сохранённый пароль шифрования в приватный файл и
задать пути в конфигурации. При scope `drive.file` использовать тот же OAuth
клиент rclone; если доступ к прежним файлам не выдаётся, владелец может выдать
новую авторизацию со scope `drive` для восстановления своей папки.
Не выполнять `init` поверх существующего репозитория.

Узнать ID доступных снимков:

```sh
export RCLONE_CONFIG=/var/lib/price-checker/secrets/google-drive-backup/rclone.conf
export RESTIC_PASSWORD_FILE=/var/lib/price-checker/secrets/google-drive-backup/restic-password
restic -r rclone:pricechecker-drive:price-checker-backups snapshots
python3 /usr/local/lib/price-checker/google-drive-backup.py restore SNAPSHOT_ID --target /srv/price-checker-recovery
```

Команда выше восстанавливает прежний **объединённый** формат. Для новых снимков:

```sh
python3 /usr/local/lib/price-checker/store-backup.py --store randewoo restore SNAPSHOT_ID --target /srv/randewoo-recovery
python3 /usr/local/lib/price-checker/store-backup.py --store ozon restore SNAPSHOT_ID --target /srv/ozon-recovery
python3 /usr/local/lib/price-checker/lamoda-backup.py restore SNAPSHOT_ID --target /srv/lamoda-recovery
```

Выбирайте ID по метке нужного магазина. Восстановление отклоняет чужой формат,
другой магазин, повреждённые файлы, существующий каталог и пути рабочих данных.
Новые снимки Randewoo/Ozon используют `price-checker-store-backup-v1` с одной
базой; формат Lamoda и восстановление старого `price-checker-database-backup-v1`
с двумя базами сохранены.

После установки бэкапов изменение приложения, убирающее локальную копию из
сбора Randewoo, выпускается обычным PR `develop` → `main`. До этого старый релиз
может продолжать делать дополнительную локальную копию. Новая версия приложения
самостоятельно копии не создаёт; локальный запуск без серверных служб требует
отдельного резервирования.

`SNAPSHOT_ID` заменить реальным ID из списка. Команды требуют новый каталог,
проверяют состав снимка и не позволяют восстановление поверх рабочих данных.
Файлы находятся в `staging/<магазин>.sqlite3`; у старого объединённого снимка
в каталоге будут обе базы Randewoo и Ozon.
Заменять рабочие базы только отдельной операцией при остановленной службе,
после сохранения текущих файлов, проверки совместимости схемы с кодом и
с соблюдением владельца/прав. Старые WAL/SHM нельзя оставлять рядом с
восстановленными файлами. Восстанавливать магазин только из его файла.
