# Ozon: ограниченный запуск Chrome на Linux VDS

17 октября 2026, результат зафиксирован в 23:56 МСК. Отдельный worktree `price-checker-ozon-design`.

Последующее обновление 18 октября: другой, созданный с нуля Linux-профиль получил публичную карточку, а после самостоятельного входа владельца — аккаунтные данные с сохранением входа и доставки после перезапуска. Пик с удалённым окном около 590 МиБ. См. [новый протокол](ozon-public-product-linux.md). Ниже описан предыдущий неудачный запуск; он не означает недоступность Ozon из любого Linux-профиля.

## Результат

Официальный Google Chrome 155.0.8059.84 запущен непосредственно на текущем Linux VDS. Проверены русский язык `ru-RU`, часовой пояс Europe/Moscow и работающие WebGL/WebGL2 через SwiftShader. Браузер использовал прямой сетевой выход VDS, подтверждённый отдельным чтением выходного IP. Через Chrome DevTools MCP проверены страница Ozon, чтение избранного с cookies аккаунта и переход на выданную Ozon страницу проверки.

Доступ к аккаунтным данным на Linux получить не удалось:

1. Главная в новом профиле без входа: 307 → 403.
2. Из сохранённого тестового Windows-профиля экспортированы 10 cookies только домена Ozon и перенесены в Linux Chrome с метаданными срока, scope, Secure/HttpOnly и SameSite. В Network запроса избранного подтверждена отправка всех 10 имён, включая cookies доступа и ID аккаунта. Ответ — 403 JSON с полями `incidentId`, `challengeURL`, `supportURL`, `timeoutSec`, `blockURL`; товарных виджетов нет.
3. Выполнен один переход на возвращённый тем же ответом HTTPS URL `/challenge.html` того же origin. Переход завершился на `/abt/challenge/fail`, HTTP 403, текст «403 Forbidden». Интервал от получения ответа до завершения навигации — 78 секунд; поле `timeoutSec` было равно 180, его точное назначение не установлено. Заголовок `Retry-After` не обнаружен.

После этого новых попыток не выполнялось. Cookies были отправлены, но принятие авторизации и выбранной доставки сервером не подтверждено. Содержимое localStorage/IndexedDB Windows-профиля в этом эксперименте не переносилось. Единственная причина различия Windows и Linux по-прежнему не выделена; русский язык, работающий WebGL и перенос cookies оказались недостаточны в проверенной комбинации.

## Память и изоляция

В системе доступно около 1,76 ГиБ RAM; до запуска свободно для выделения было около 1,3 ГиБ. Браузер и Xvfb работали в отдельной временной systemd-службе от пользователя `ozonbrowser`, с `MemoryMax=768M`, `MemoryHigh=640M`, `MemorySwapMax=128M`, `CPUQuota=100%` и ограничением времени 30 минут. Перезапуск службы отключён.

| Измерение cgroup, включая Chrome и Xvfb | Значение |
| --- | --- |
| Текущее потребление до обращения к Ozon | Около 269 МиБ |
| Наибольший зафиксированный пик | Около 427 МиБ |
| Использование swap браузером | 0 |
| События `memory.high`, `memory.max`, OOM и OOM kill | 0 |
| Доступная память хоста в последнем замере с браузером | Около 1004 МиБ |
| Доступная память хоста после остановки браузера | Около 1325 МиБ |

Замерен запуск и обработка отказа/проверки Ozon. Полная страница магазина, авторизованный проход по 30 товарам и длительная работа не были достигнуты; их потребление памяти этим замером не определяется. Ограничение 2 ГБ не стало препятствием именно для выполненного теста.

У renderer подтверждены user/PID namespaces, seccomp, NoNewPrivileges и отсутствие capabilities. Флаги отключения sandbox не добавлялись. У программного GPU-процесса seccomp отсутствовал, как и в предыдущем графическом эксперименте; этот вариант не объявляется готовой конфигурацией для эксплуатации. Действовали изоляция пользователя и ограничения systemd-службы.

## Завершение

Chrome закрыт через CDP; временная служба завершилась, SSH-туннель и MCP отключены. Диагностические порты на компьютере владельца и VDS больше не слушают. Временно открывавшийся Windows-профиль для экспорта cookies также закрыт.

Price Checker остался `active/running`, `NRestarts=0`. Рабочие базы и настройки Randewoo не менялись. Расписание Ozon не включено.

Профили и сырые данные сохранены приватно: локально в игнорируемой `.secrets/ozon-server/linux-browser-check/`, на VDS — в отдельных каталогах браузерной диагностики. Значения cookies, challenge-токены, ID аккаунта и точный адрес в этот отчёт не включены.

Ранее успешное [аккаунтное чтение в Windows Chrome через IP VDS](ozon-account-browser-check.md) остаётся подтверждённым. Автономный сбор непосредственно на Linux VDS пока не работает.
