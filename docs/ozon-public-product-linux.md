# Ozon: публичная карточка и полноценный вход на Linux

18 октября 2026. Публичный результат зафиксирован в 00:13 МСК, проверка входа и перезапуска завершена в 00:21 МСК. Отдельный worktree `price-checker-ozon-design`.

## Подтверждённый результат

На текущем Linux VDS получены реальные данные Ozon через штатный Google Chrome: публичная карточка без входа, а после самостоятельного входа владельца — последние 30 избранных, корзина, выбранная доставка, обычная и проверенная цена Ozon Карты одной карточки, числовой ID продавца. Вход и доставка сохранились после немедленного перезапуска браузера без повторного кода.

Подмена User-Agent или отпечатка Windows не использовалась. Chrome работал в графическом режиме через Xvfb, с `ru-RU`, Europe/Moscow и SwiftShader. Все товарные ответы читались из Network через Chrome DevTools MCP. Рабочие базы Randewoo не использовались.

## Публичная карточка

Для эксперимента создан новый постоянный профиль непосредственно на VDS. Cookies аккаунта из Windows в него не переносились, ручного входа на этом этапе не было.

Начальная навигация напрямую на выбранную публичную карточку получила 307 → 403. Затем один GET JSON той же карточки из этого браузерного контекста вернул `200 application/json;charset=UTF-8`, около 167 КБ. Зафиксирован и последующий самостоятельный переход браузера на HTML карточки с HTTP 200, без ручного обновления. Проверены точный SKU, доступность, обычная и банковская цена, числовой ID продавца. Положительный ID аккаунта в товарном ответе отсутствовал.

Отдельная маркировка банковской цены как цены Ozon Карты на гостевом этапе не подтверждалась; она проверена после входа вместе со списком банков для того же SKU.

Нельзя приписывать успех одному изменению: относительно предыдущих неудачных запусков изменились профиль, стартовая страница и состояние проверки сайта. Конкретная причина прежних 403 не выделена.

## Самостоятельный вход на сервере

Владелец увидел серверный Chrome через временную локальную страницу удалённого окна, сам ввёл телефон/код на Ozon и выбрал адрес в Грозном. В диагностике читались только проверенные GET товарных и аккаунтных страниц; тела запросов входа с телефоном/кодом не извлекались.

| Чтение после входа | Результат |
| --- | --- |
| Избранное | JSON 200; тот же аккаунт и отпечаток выбранной доставки; сортировка `last_added`, последние 30 настоящих избранных, полный результат для лимита |
| Цены в избранном | У 23 из выбранных товаров есть цена; 7 недоступны, отсутствующая цена остаётся пустой |
| Корзина | JSON 200; тот же аккаунт/доставка; 3 строки по одной единице, полнота сверена с `master.summary` |
| Одна карточка | JSON 200; тот же аккаунт/доставка и SKU; обычная цена, цена Ozon Карты, числовой ID продавца |
| Условия оплаты | JSON 200 для возвращённого карточкой списка банков того же SKU; Ozon Банк присутствует |

Сопоставление аккаунта и доставки выполнено теми же существующими парсерами и приватным эталоном, которые использовались для Windows-проверки. Для избранного дополнительно проверен явный `isLoggedIn=true`.

## Проверка перезапуска

Chrome закрыт через CDP и снова запущен с тем же профилем. Карточка открылась с HTTP 200. Последующий GET избранного также получил JSON 200: аккаунт и доставка совпали, те же 30 SKU сохранились в том же порядке. Повторного ввода телефона/кода не было.

Проверен один немедленный перезапуск. Двухчасовой интервал, длительное истечение сессии и несколько последовательных плановых циклов ещё не проверены. В последующей отдельной [HTTP-проверке](ozon-http-linux-session.md) новая Linux-сессия дала JSON 200 избранного, корзины, карточки и банков при закрытом Chrome. Прежняя диагностическая пауза не сбрасывалась.

## Ресурсы и завершение

Chrome, Xvfb, x11vnc и мост удалённого окна работали в отдельной временной systemd-службе с общим лимитом 768 МиБ RAM, `MemoryHigh=640M`, `MemorySwapMax=128M`, одним ядром CPU и ограничением времени запуска. У renderer подтверждён sandbox. Особенности программного GPU-процесса, отмеченные в [предыдущем отчёте](ozon-linux-browser-check.md), сохраняются.

| Наибольший зафиксированный пик cgroup | Значение |
| --- | --- |
| Первый проход публичной карточки с Chrome и Xvfb | Около 541 МиБ |
| Ручной вход и аккаунтные чтения, включая удалённое окно | Около 590 МиБ |
| Повторный запуск и повторное чтение избранного | Около 483 МиБ |

В замерах не было OOM, событий достижения `memory.high`/`memory.max` или использования swap браузером. После завершения теста на хосте доступно около 1338 МиБ. Полный проход по всем 30 карточкам не выполнялся; эти значения не задают гарантированный эксплуатационный бюджет.

Для удалённого окна установлен x11vnc с новыми библиотеками; статические файлы noVNC и модуль websockify распакованы из пакетов Ubuntu в отдельный каталог. Системный Node не заменялся. Временный доступ был защищён VNC-паролем и доступен через loopback и SSH-туннель. При завершении Chrome, удалённое окно, MCP и туннель закрыты; диагностические порты больше не слушают. Постоянный профиль с входом сохранён приватно на VDS.

Price Checker остался `active/running`, `NRestarts=0`. Рабочие базы, настройки и процессы Randewoo не менялись. Расписание Ozon, новый интерфейс и история цен ещё не включены.

Сетевые ответы, данные сессии, выбранные SKU и точный адрес находятся только в игнорируемой `.secrets/ozon-server/public-login-check/` и отдельных приватных каталогах VDS. Данные входа в этот документ не включены.

После успешной HTTP-проверки основной кандидат для worker — HTTP с отдельной БД Ozon; сохранённый серверный профиль остаётся средством восстановления сессии. Нужны пауза при потере аккаунта/доставки или отказе доступа, измерение полного прохода и несколько проверок с интервалом два часа.
