# Базы и резервные копии

Раздел `/storage` работает под существующим входом Price Checker. Ссылки находятся
в меню всех магазинов. Четыре вкладки: обзор, данные, миграции и резервные копии.
На вкладке копий доступны сами копии и отдельная таблица попыток резервирования.

## Просмотр

Разрешённые таблицы и поля перечислены в `src/storage-browser.js`. Соединения открываются
только для чтения. Токены устройств, данные входа, сообщения Telegram, сырые ответы
источников и произвольные SQL-запросы не доступны через этот раздел.

Серверная пагинация: 50, 100 или 200 строк, поиск, фильтры и сортировка. Параметры
сохраняются в адресе. Для наблюдений фиксируется верхний rowid, поэтому новые сборы
не сдвигают страницы. Кнопка «Обновить» получает новую границу. Это не исторический
снимок изменяемых товаров и статусов заданий. Количество неизменяемых наблюдений без
текстового поиска кешируется до 30 секунд для той же границы и фильтров.

Даты фильтра и интерфейса — по Москве, последний день включается полностью.
Цены интерфейса — в рублях. CSV содержит исходные значения: технические названия
столбцов, денежные поля в копейках и даты как в базе. Подсказка ссылок экспорта
указывает это различие. NULL не подменяется нулём. Формулы Excel экранируются.

Чтение работает в отдельных потоках, максимум два запроса одновременно. Страница
ограничена 20 секундами, CSV — 120 секундами; при отключении клиента работа отменяется.
Выгрузка идёт порциями по 500 строк с учётом скорости скачивания. При превышении
времени соединение прерывается: следует сузить период. Экспорт товарных баз держит
снимок SQLite и может временно задержать checkpoint WAL. Для служебного журнала
транзакция чтения заканчивается после каждой порции, до ожидания скачивания:
медленный клиент не держит блокировку писателей журнала. Изменяемые статусы журнала
в таком экспорте отражают состояние на момент чтения соответствующей порции.

## Журнал резервирования

`<data>/backup-journal/events.sqlite3` — отдельная служебная база, не четвёртый магазин.
Журнал имеет собственную миграцию с контрольной суммой. `runs` хранит попытки,
`artifacts` — известные файлы и снимки. Устанавливается с владельцем root и доступом
на чтение группе pricechecker; веб-приложению не выдаются ключи restic/rclone.

Писатели: инструменты деплоя, резервирования магазинов и обслуживания облака.
Учитываются ожидание, создание, отправка, проверка восстановления, пропуски при
отсутствии изменений и ошибки. Созданная копия сохраняется в журнале даже при ошибке
последующей проверки восстановления. Ручная команда verify также регистрируется.

При следующем запуске писателя незавершённая операция умершего процесса становится
прерванной. В Linux сравниваются PID, boot ID и время старта процесса.

Существующие локальные копии обнаруживаются по pre-deploy-манифестам. Облачные —
по полному каталогу restic во время ежедневного обслуживания. Повторный импорт
не создаёт дубликаты. Неизвестное время и степень проверки остаются неизвестными;
история прошлых попыток не выдумывается. Удаление копии сохраняет её запись.
Сбой чтения облачного каталога не является доказательством удаления копий.
Интерфейс показывает время последней проверки наличия. Копии на личном компьютере
автоматически не учитываются.

Обслуживание создаёт согласованный снимок самого журнала, отправляет его с тегом
`price-checker-journal` и проверяет восстановление. Только после успешной проверки
применяется отдельное хранение: последние 7 снимков, ежедневные за 30 дней, ежемесячные
за 12 месяцев. Это не меняет правила хранения товарных копий. Текущая операция
обслуживания в снимке журнала ещё не завершена. История строк журнала не удаляется.

## Установка

Системные Python-скрипты находятся вне релиза и не заменяются обычным CI-деплоем.
Перед первым выпуском из проверенного сохранённого коммита выполнить от root:

```sh
bash scripts/setup-storage-browser.sh --update
bash scripts/setup-deploy.sh --update
```

Первый установщик ждёт освобождения очереди резервирования, держит блокировку деплоя,
сохраняет прежние файлы, обновляет писателей и разрешения systemd для журнала.
Расписания сохраняются, резервирование не запускается. Второй обновляет entrypoint
деплоя вместе с модулем журнала без перезапуска приложения. Облачный каталог появится
после штатного ежедневного обслуживания. Затем — PR develop → main и обычный деплой.

Если журнал ещё не установлен или недоступен, обзор сообщает об этом; просмотр трёх
товарных баз остаётся доступен. `/api/health` продолжает проверять товарные хранилища.

## Проверки

Проверяются страницы при поступлении новых наблюдений, поиск, даты, ограничения API,
полный CSV, журнал ошибок, прерванные операции, повторный импорт, исчезнувшие копии,
контрольные суммы миграций. Проверка глубокой страницы использует 100 000 наблюдений.
Компонентные проверки выполняются в jsdom, без запуска браузера.
