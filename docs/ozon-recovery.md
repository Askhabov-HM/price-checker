# Чтение Ozon через постоянный серверный Chrome

Временный отказ, включая HTTP 403, больше не ставит автосбор на постоянную ручную
паузу: история сохраняет ошибку, а следующая попытка назначается по независимому
расписанию Ozon. Явный `Retry-After` соблюдается; при 429 без такого заголовка
используется следующий плановый срок. При запуске приложения снимаются прежние
паузы от временных ошибок и прерванных сборов. Потеря входа или другой аккаунт
по-прежнему останавливают сбор до подтверждения владельцем. Настройки расписаний
и сохранённые цены при этом не меняются.

Каждый сбор Ozon целиком выполняется через серверный Chrome с сохранённым авторизованным Linux-профилем. Приложение подключается через приватный Unix socket `/run/price-checker-ozon-recovery.sock`. Прямые HTTP-запросы из Node.js в сборе отсутствуют, включая первый запрос после перезапуска. Если браузер недоступен, сбор останавливается; запасного HTTP-пути нет. Новые наблюдения получают источник `browser`. Сами запросы внутри Chrome по-прежнему используют HTTPS и cookies браузера.

При общем сборе браузер читает всё избранное с пагинацией вместе с ценами из списка через проверенный GET endpoint. Приложение проверяет прежний аккаунт и User-Agent. Доставка не является условием сбора; виджет адреса не требуется. Корзина, карточки и банковские условия в общем сборе не запрашиваются. Явная проверка отдельной карточки сохраняется как отдельное действие; для неё подтверждается точный SKU, а банковские условия разрешены только для той же карточки. Чтение не меняет аккаунт, адрес, корзину или избранное.

Socket с `Accept=no` запускает единственную службу `price-checker-ozon-recovery.service` от `ozonbrowser`. Она выдаёт браузер одному подключению на весь обход; остальные подключения ожидают в ограниченной очереди. В режиме сбора Chrome работает с Xvfb, CDP передаётся через приватные pipes: TCP-порт отладки, VNC и удалённое окно не запускаются. Вкладка и профиль сохраняются между обходами. На один обход разрешено не более 220 последовательных API-чтений; при освобождении подключения счётчик и разрешение банковских условий сбрасываются без новой навигации.

После завершения или отмены сбора приложение освобождает подключение. Уже начатое браузерное чтение заканчивается перед передачей профиля следующему сбору. На сервере Chrome и Xvfb работают **круглосуточно без закрытия по простою**, интервал сбора Ozon остаётся **60 минут**. Расписание Randewoo независимо. Между сборами приложение не отправляет запросы Ozon и не обновляет страницу; собственные фоновые запросы сайта этим не запрещаются. Ранее применявшийся таймер 70 минут отключён.

Сохранённые cookies приложения передаются при первом чтении после запуска Chrome и заполняют лишь отсутствующие или истёкшие cookies: действующие значения профиля имеют приоритет. Повторное подключение не затирает живую сессию старой копией. После браузерного ответа приложение сначала проверяет аккаунт и User-Agent и только затем сохраняет свежие scoped cookies для восстановления профиля. Ошибки и чужой аккаунт не заменяют сохранённую сессию. При падении worker текущий сбор останавливается без автоматического повтора. Служба раз в 30 секунд проверяет наличие процесса и при необходимости запускает Chrome на `about:blank`, без навигации на Ozon. Переход на сайт и подстановка cookies выполняются при следующем сборе. Саму службу после аварии перезапускает systemd, при загрузке сервера она запускается автоматически.

Обычные cookies и cookies фиксированного first-party partition `https://ozon.ru` с `hasCrossSiteAncestor=false` хранятся в отдельных jars. Совпадение имени, домена и пути между этими контекстами допустимо; внутри одного контекста неоднозначные дубликаты по-прежнему отклоняются. Чужие partitions не импортируются, непрозрачный контекст отклоняется. Partitioned cookies сохраняют Secure, срок действия и partition key при передаче обратно в Chrome. Старые session.json без дополнительного jar остаются читаемыми.

Отдельный режим [входа владельца](ozon-login.md) сначала закрывает общий Chrome, затем запускает интерактивный браузер с тем же профилем и временным VNC на loopback. Очередь сбора ждёт освобождения профиля. После подтверждения входа cookies сохраняются и интерактивный Chrome обязательно закрывается. Фоновая служба затем открывает обычный Chrome с тем же сохранённым профилем.

Отказ доступа в браузере, его отключение, истёкший вход, несовпадение контекста и явное ожидание источника останавливают очередь. Ошибка ответа отдельной карточки сохраняется в её истории; оставшиеся товары проверяются, итог обхода становится `partial`. Второй браузер и возврат к HTTP внутри этого обхода не запускаются. Ограничения `Retry-After` и backoff для 429 сохраняются. Автоматического входа по телефону/коду нет.

Обязательная двухчасовая пауза ручных проверок удалена по запросу владельца. Явное ожидание источника и backoff при 429 сохраняются. Интервал два часа относится только к расписанию, которое по умолчанию выключено и не включается установкой worker.

## Установка на Linux

Перед первой навигацией Chrome получает действующие scoped cookies приложения через тот же приватный socket. Это позволяет восстановить тот же аккаунт, если браузер потерял сессионные cookies при перезапуске. Домен, путь, срок действия, Secure/Host-префиксы и SameSite проверяются повторно в worker; cookies неизвестной области и bootstrap без метаданных не переносятся. Затем аккаунт обязательно проверяется по ответу браузера. Адрес не сравнивается и не настраивается. Новая авторизация по телефону или коду не выполняется.

Нужны Chrome, Xvfb, сгенерированная системная локаль `ru_RU.UTF-8`, пользователь `ozonbrowser` и уже авторизованный профиль под `/var/lib/price-checker-ozon-browser/`. После установки release выполнить от root:

```sh
bash /opt/price-checker/current/scripts/setup-ozon-recovery.sh /var/lib/price-checker-ozon-browser/<saved-session>/profile
```

Socket доступен только `pricechecker`, профиль — только пользователю браузера. Приватная конфигурация пути находится в `/etc/price-checker-ozon-recovery.env` с правами 0600. Служба вместе с дочерними процессами ограничена MemoryMax=1024M, MemoryHigh=896M, SwapMax=128M, CPUQuota=100% и TasksMax=256. Общего RuntimeMaxSec нет: ограничены отдельный сбор (590 секунд) и окно входа (20 минут в приложении, 21 минута в службе). По замеру 20 октября 2026 Chrome со служебными процессами занимал около 617 МиБ (пик 688 МиБ), доступная память сервера — около 775 МиБ. Это позволяет держать один браузер постоянно, но не доказывает отсутствие роста памяти при длительной работе.

`OZON_BROWSER_IDLE_MINUTES=0` отключает закрытие по простою и включает поддержание процесса 24/7; это значение по умолчанию и настройка сервера. Для экономного режима по-прежнему допустимы целые значения от 1 до 1440 минут: тогда Chrome запускается при сборе и закрывается после указанного простоя. Установщик сохраняет уже заданную настройку. Переменная не меняет интервалы сбора. После её изменения нужно перезапустить `price-checker-ozon-recovery.service`; активный браузер при этом закроется. Установщик включает автозапуск socket и службы. Для полного отключения остановить и отключить оба: `systemctl disable --now price-checker-ozon-recovery.service price-checker-ozon-recovery.socket`.

Установщик также сохраняет в этом файле `LANG=ru_RU.UTF-8`, `LC_ALL=ru_RU.UTF-8` и `LANGUAGE=ru_RU:ru`. Их наследуют Chrome в worker и отдельное серверное окно: русский язык интерфейса задаётся независимо от языка сайтов и HTTP-заголовка `Accept-Language`. Изменение применяется при следующем запуске браузера; системная локаль остальных служб не меняется.

Для перехода с прежнего worker нужны новые `price-checker-ozon-recovery.service` и socket с `Accept=no`, остановка старого socket и его worker, затем `systemctl daemon-reload` и запуск socket. Установщик выполняет этот переход, сохраняет существующие параметры окружения и добавляет отсутствующие значения по умолчанию. Прежняя template-служба `price-checker-ozon-recovery@.service` новой схемой не используется. Самостоятельный `scripts/ozon-browser.js` сохраняет одноразовый протокол; его нельзя запускать одновременно с общей службой на одном профиле.

## Окружение браузера

Общий файл окружения также задаёт `TZ=Europe/Moscow`, `OZON_BROWSER_SCREEN=3840x2160`, `OZON_BROWSER_WINDOW=1282x1344`, `OZON_BROWSER_SCALE=1.5` и `OZON_BROWSER_GRAPHICS=swiftshader`. Размер Xvfb указан в физических пикселях: при масштабе 1,5 Chrome показывает `screen.width=2560` и `screen.height=1440`; внутренний размер страницы — `1282×1257`, как в локальном Chrome при сравнении. Список языков нового выделенного профиля задаётся через `intl.accept_languages` и `intl.selected_languages` в `Default/Preferences`: `ru,en-US,en,zh-CN`. Личный профиль Windows для этого не переносится.

`OZON_BROWSER_GRAPHICS=auto` включает обычный выбор графического backend. На текущей VDS в этом режиме WebGL оказался недоступен, поэтому установщик явно выбирает SwiftShader: с ним WebGL работает. Прежние отключения фоновой сети, обновления компонентов и синхронизации удалены. `--disable-blink-features=AutomationControlled` выравнивает `navigator.webdriver` с локальным Chrome, сохраняя управление через приватный CDP pipe. Настройка прокси, пропуск первого запуска и проверки браузера по умолчанию сохраняются. ОС Linux и виртуальное оборудование остаются отличными от Windows.

Для полноценного набора шрифтов на Ubuntu установить `fonts-noto-core`, `fonts-noto-color-emoji`, `fonts-dejavu-core`, `fonts-croscore`, `fonts-crosextra-carlito` и `fonts-crosextra-caladea`. Для смены профиля сначала закрыть серверный Chrome, создать отдельный каталог под `/var/lib/price-checker-ozon-browser/` с владельцем `ozonbrowser` и правами 0700, затем заменить только `OZON_BROWSER_PROFILE` в общем файле окружения. Прежний каталог сохраняется для возврата; история цен и привязка аккаунта не меняются. Новый профиль потребует входа владельца.

## Отдельный маршрут Ozon

`OZON_PROXY_URL=http://127.0.0.1:17891` задаёт один локальный HTTP-прокси для HTTP-сборщика Ozon и Chrome в recovery worker. Значение хранится в `/etc/price-checker-ozon-proxy.env` с правами 0600; HTTP-сборщику нужен этот файл через systemd drop-in основного приложения. Worker читает его через `EnvironmentFile`; отдельной службе серверного окна также нужен этот файл. При ошибке настроенного прокси прямого повторного подключения нет. Без переменной сохраняется обычное прямое соединение. Глобальный dispatcher Node.js не меняется.

На сервере выбран узел «Казахстан — 1»: `astana.vkusnews.com:443`, alias `eos-cd52253302e3`. При предыдущем открытии публичной главной страницы его выходной IPv4 был `83.229.15.247`; провайдер может позднее изменить адрес узла. Для него установлена отдельная служба `scripts/systemd/price-checker-ozon-proxy.service`: Mihomo слушает только `127.0.0.1:17891`, использует единственный узел и правило `MATCH` на него, без автоматического выбора и DIRECT fallback. Закрытая конфигурация `/etc/price-checker-ozon-proxy/config.json` содержит копию параметров этого узла из существующего provider и не хранится в репозитории. Основной прокси Telegram на порту 17890 и маршруты Randewoo остаются прежними.

Служба прокси включена в автозагрузку. Для `price-checker.service`, `price-checker-ozon-recovery@.service` и отдельного `price-checker-ozon-browser.service` установлены drop-in `ozon-proxy.conf` с `Wants=price-checker-ozon-proxy.service`, `After=price-checker-ozon-proxy.service` и `EnvironmentFile=/etc/price-checker-ozon-proxy.env`. После изменения маршрута основное приложение нужно перезапустить; Chrome получит настройку при следующем открытии. Установка маршрута не открывает браузер, не восстанавливает вход и не возобновляет приостановленный сбор.

## Проверки

20 октября 2026 реализована и установлена общая служба с `OZON_BROWSER_IDLE_MINUTES=60`. На Linux прошли 26 согласованных тестов повторного использования, таймера, очереди, отмены, восстановления после падения, приоритета cookies профиля, HTTP-синхронизации после проверки аккаунта и ручного входа. На Windows прошли 25 тестов, один Unix socket сценарий пропущен. Часовой таймер проверен управляемым временем, без ожидания реального часа. Проверены shell-синтаксис установщика и systemd units.

При проверке на реальном сервере два последовательных подключения использовали один процесс Chrome и получили HTTP 200. После перезапуска в ответах избранного отсутствует `userInfo`, поэтому текущая проверка аккаунта не проходит; это не подтверждённая потеря входа. Цены и настройки расписания этой проверкой не менялись. На момент этой проверки интервал сбора был 120 минут. Затем по отдельному запросу владельца простой Chrome увеличен до 70 минут, а интервал Ozon уменьшен до 60 минут. Расписание Randewoo сохранено. Пауза до подтверждения аккаунта остаётся; сами параметры времени не заменяют подтверждение входа. Для последнего изменения конфигурации новые тесты не запускались без отдельного одобрения.

После повторного входа владельца сохранение сначала останавливалось с ошибкой «Неоднозначный partition-контекст cookies Ozon». На сервере подтверждены обычная и first-party partitioned версии одной cookie. Исправлены раздельное хранение, HTTP-обновление, истечение срока и восстановление partition key в Chrome. Прошли 16 согласованных тестов импорта/сессии/входа на Windows и Linux и отдельный существующий тест совместимости first-party импорта. Исправление установлено на сервер: прежний аккаунт успешно подтверждён, сохранены 11 обычных и одна partitioned cookie в файле с правами 0600. Интерактивный Chrome закрыт, пауза снята, часовой сбор возобновлён. Новый общий сбор цен в рамках этого исправления не запускался.

20 октября 2026 по разрешению владельца выполнено сравнение браузерного окружения и повторное открытие Ozon. У нового выделенного профиля подтверждены экран `2560×1440`, масштаб `1.5`, размер страницы `1282×1257`, языки `ru,en-US,en,zh-CN`, часовой пояс `Europe/Moscow` и `navigator.webdriver=false`. Установлено 206 семейств шрифтов. В режиме `auto` WebGL недоступен; со SwiftShader он работает, поэтому на этой VDS выбран SwiftShader. В штатном серверном окне через Казахстан (`83.229.15.247`) загрузилась гостевая страница избранного без сообщения про VPN. Затем владелец вошёл вручную: приложение подтвердило прежний аккаунт, сохранило HTTP-сессию с правами 0600 и закрыло Chrome. Требование действий снято, существующее расписание возобновлено. Отдельный общий сбор после входа вручную не запускался. Прежний профиль сохранён для возврата.

Ранние эксперименты 18 октября 2026 подтвердили серверный профиль и схему HTTP 403 → Chrome → обновление cookies → HTTP 200, включая изолированную копию VDS. Это исторические проверки прежнего восстановления cookies.

Тесты текущей схемы проверяют отсутствие прямого HTTP при холодном старте, ошибке и недоступности Chrome, сохранение браузерных цен, полную пагинацию избранного, одну сессию на обход, отсутствие закрытия при виртуальных 24 часах простоя, восстановление процесса, исключительное владение профилем при входе, проверку аккаунта/SKU, банковские условия, ограничения GET, размер ответа, явное ожидание источника и отмену socket. Длительная стабильность доступа не гарантируется; истёкший вход может потребовать участия владельца. Отказ от прямого HTTP сам по себе не доказывает, что именно HTTP вызывал прежние ограничения.

20 октября 2026 установлен режим только через Chrome с `OZON_BROWSER_IDLE_MINUTES=0` и автозапуском службы. Прошли 35 согласованных тестов на Linux и 34 на Windows (один Unix socket-тест пропущен на Windows). Первый полный сбор после установки успешно прочитал 110 товаров на пяти страницах избранного, все пять API-ответов — 200, свежие цены получены для 82 товаров. Прямые HTTP-запросы из Node.js были запрещены контрольным обработчиком и не выполнялись; карточки товаров не запрашивались. Нужный аккаунт подтверждён без нового входа. После освобождения подключения тот же Chrome остался запущен; служба занимала около 544 МиБ, пик — 611 МиБ, доступная память сервера — около 775 МиБ. Часовой интервал и настройки Randewoo сохранены. У одного недоступного товара сохранились прежняя цена с историческим источником `http` и её исходная дата: это сохранённая история, а не новый HTTP-запрос.
