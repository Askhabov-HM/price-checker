# Чтение Ozon через серверный браузер после HTTP 403

Основной сборщик начинает обход через HTTP. После первого HTTP 403 без `Retry-After` он открывает приватный Unix socket `/run/price-checker-ozon-recovery.sock` и переключает оставшийся обход на один серверный Chrome с сохранённым авторизованным Linux-профилем. Это чтение самих данных через браузер, а не обновление cookies ради повторного HTTP-запроса. Новые наблюдения получают источник `browser`.

Браузер читает избранное, корзину, карточки и условия Ozon Карты через проверенный GET endpoint. Приложение проверяет прежний аккаунт и доставку в каждом ответе страницы, точный SKU карточки и User-Agent. Банковские условия разрешены только для последней прочитанной карточки; если 403 впервые встретился на банковских условиях, сначала в браузере проверяется та же карточка. Изменений аккаунта, адреса, корзины и избранного нет.

Socket запускает отдельный systemd worker от `ozonbrowser`. Chrome работает с Xvfb, CDP передаётся через приватные pipes: TCP-порт отладки, VNC и удалённое окно не запускаются. На весь обход приходится одна навигация и не более 220 последовательных API-чтений. Приложение не получает cookies браузера; авторизация сохраняется в его приватном профиле. При завершении, ошибке или отмене обхода socket закрывается, Chrome и Xvfb останавливаются. Общая блокировка сборщика удерживается до завершения очистки.

Отказ доступа в самом браузере, его отключение, истёкший вход, несовпадение контекста и явное ожидание источника останавливают очередь. Ошибка ответа отдельной карточки сохраняется в её истории; оставшиеся товары проверяются, итог обхода становится `partial`. Второй браузер и возврат к HTTP внутри этого обхода не запускаются. 401, 429, сетевые ошибки и 403 с `Retry-After` не запускают браузерный режим. Автоматического входа по телефону/коду нет.

Обязательная двухчасовая пауза ручных проверок удалена по запросу владельца. Явное ожидание источника и backoff при 429 сохраняются. Интервал два часа относится только к расписанию, которое по умолчанию выключено и не включается установкой worker.

## Установка на Linux

Нужны Chrome, Xvfb, пользователь `ozonbrowser` и уже авторизованный профиль под `/var/lib/price-checker-ozon-browser/`. После установки release выполнить от root:

```sh
bash /opt/price-checker/current/scripts/setup-ozon-recovery.sh /var/lib/price-checker-ozon-browser/<saved-session>/profile
```

Socket доступен только `pricechecker`, профиль — только пользователю браузера. Приватная конфигурация пути находится в `/etc/price-checker-ozon-recovery.env` с правами 0600. Worker ограничен MemoryMax=768M, MemoryHigh=640M, SwapMax=128M, CPUQuota=100%, TasksMax=256, RuntimeMaxSec=600 и собственным таймаутом 590 секунд. Постоянного процесса браузера нет. Для сервера с 2 ГБ RAM это временный лимит, а не гарантия запуска при любом остатке памяти.

При обновлении уже установленного worker нужно установить актуальный `scripts/systemd/price-checker-ozon-recovery@.service` в `/etc/systemd/system/` и выполнить `systemctl daemon-reload`; профиль и его конфигурацию заменять не требуется. Для отключения: `systemctl disable --now price-checker-ozon-recovery.socket`.

## Проверки

Ранние эксперименты 18 октября 2026 подтвердили серверный профиль и схему HTTP 403 → Chrome → обновление cookies → HTTP 200, включая изолированную копию VDS. Это исторические проверки прежнего восстановления cookies.

Тесты новой схемы проверяют переключение всей очереди после одного HTTP 403, сохранение браузерных цен, одну сессию на обход, закрытие браузера, остановку на его отказе, проверку аккаунта/адреса/SKU, банковские условия, ограничения GET, размер ответа, явное ожидание источника и отмену socket. Длительная стабильность доступа не гарантируется; истёкший вход может потребовать участия владельца.
