# Восстановление HTTP-сессии Ozon

Основной сборщик использует HTTP. После первого HTTP 403 за цикл он может один раз обратиться к локальному Unix socket `/run/price-checker-ozon-recovery.sock`. При отсутствии socket сохраняется прежняя остановка с `action_required`.

Socket запускает отдельный systemd worker от `ozonbrowser`. Worker открывает одну страницу в сохранённом авторизованном Linux-профиле и делает одно явное чтение API этой страницы. Для отказа на условиях банковской цены используется карточка того же SKU. Страница сама может делать несколько обычных запросов браузера. Изменений корзины, адреса и аккаунта worker не выполняет.

Chrome работает с Xvfb, CDP передаётся через приватные pipes процесса: TCP-порт отладки, VNC и удалённое окно не запускаются. После экспорта Chrome и Xvfb закрываются. Только затем приложение получает результат, проверяет прежний аккаунт, доставку, User-Agent, SKU карточки, область cookies и сохраняет сессию. Контрольное HTTP-чтение выполняется один раз, без перенаправлений. Цена сохраняется только из проверенного HTTP-ответа.

Блокировка сборщика удерживается всё это время. Второй отказ в том же цикле, ошибка браузера, несовпадение контекста или истёкший вход останавливают очередь и требуют внимания владельца. 401, 429, сетевые ошибки и 403 с Retry-After не запускают восстановление. Автоматического входа по телефону/коду нет. Прерывание приложения отменяет обращение к socket; worker также ограничен собственным таймаутом и systemd.

## Установка на текущем Linux-сервере

Нужны Chrome, Xvfb, пользователь `ozonbrowser` и уже авторизованный профиль под `/var/lib/price-checker-ozon-browser/`. После обновления release выполнить от root:

```sh
bash /opt/price-checker/current/scripts/setup-ozon-recovery.sh /var/lib/price-checker-ozon-browser/<saved-session>/profile
```

Установка включает только socket, без запуска Chrome и без изменения расписания. Доступ к socket имеет только `pricechecker`; профиль недоступен веб-процессу. Конфигурация пути к профилю хранится в `/etc/price-checker-ozon-recovery.env` с правами 0600. Worker ограничен MemoryMax=768M, MemoryHigh=640M, SwapMax=128M, CPUQuota=100%, TasksMax=256 и RuntimeMaxSec=55. Постоянного процесса браузера нет. Для сервера с 2 ГБ RAM это временный лимит, а не обещание успешного запуска при любом остатке памяти.

Для отключения: `systemctl disable --now price-checker-ozon-recovery.socket`. Изолированная БД Ozon, двухчасовая пауза и расписание не изменяются установкой или отключением worker. Завершение уже запущенного worker ограничено таймаутом; повторных циклов восстановления внутри него нет.

Ручной эксперимент 18 октября 2026 подтвердил 403 со старой сессией → запуск сохранённого Chrome → обновление cookies → закрытие Chrome → HTTP 200. Долговечность сессии и восстановление при каждом возможном отказе этим не гарантируются.

Серверная проверка нового socket-worker в тот же день прошла на отдельной копии приложения и БД: настоящий HTTP 403 со старой сессией, один запуск worker, контрольная карточка 200 и условия Ozon Карты 200. Сохранена одна успешная HTTP-цена. Боевая БД и сессия не изменялись, расписание осталось выключено, отладочные порты закрыты. Linux-тесты также проверяют отмену ожидания socket и отсутствие второго восстановления в очереди.
