# Чтение Ozon через серверный браузер после HTTP 403

Основной сборщик начинает обход через HTTP. После первого HTTP 403 без `Retry-After` он открывает приватный Unix socket `/run/price-checker-ozon-recovery.sock` и переключает оставшийся обход на один серверный Chrome с сохранённым авторизованным Linux-профилем. Это чтение самих данных через браузер, а не обновление cookies ради повторного HTTP-запроса. Новые наблюдения получают источник `browser`.

При общем сборе браузер читает последние 30 избранных вместе с ценами из списка через проверенный GET endpoint. Приложение проверяет прежний аккаунт и User-Agent. Доставка не является условием сбора; виджет адреса не требуется. Корзина, карточки и банковские условия в общем сборе не запрашиваются. Явная проверка отдельной карточки сохраняется как отдельное действие; для неё подтверждается точный SKU, а банковские условия разрешены только для той же карточки. Чтение не меняет аккаунт, адрес, корзину или избранное.

Socket запускает отдельный systemd worker от `ozonbrowser`. В режиме сбора Chrome работает с Xvfb, CDP передаётся через приватные pipes: TCP-порт отладки, VNC и удалённое окно не запускаются. На весь обход приходится одна навигация и не более 220 последовательных API-чтений. Авторизация сохраняется в приватном профиле. При завершении, ошибке или отмене обхода socket закрывается, Chrome и Xvfb останавливаются. Общая блокировка сборщика удерживается до завершения очистки. Отдельный режим [входа владельца](ozon-login.md) временно добавляет просмотр через VNC на loopback; после подтверждения входа cookies передаются приложению через приватный socket и сохраняются в HTTP jar.

Отказ доступа в самом браузере, его отключение, истёкший вход, несовпадение контекста и явное ожидание источника останавливают очередь. Ошибка ответа отдельной карточки сохраняется в её истории; оставшиеся товары проверяются, итог обхода становится `partial`. Второй браузер и возврат к HTTP внутри этого обхода не запускаются. 401, 429, сетевые ошибки и 403 с `Retry-After` не запускают браузерный режим. Автоматического входа по телефону/коду нет.

Обязательная двухчасовая пауза ручных проверок удалена по запросу владельца. Явное ожидание источника и backoff при 429 сохраняются. Интервал два часа относится только к расписанию, которое по умолчанию выключено и не включается установкой worker.

## Установка на Linux

Перед навигацией Chrome получает действующие cookies из scoped HTTP jar приложения через тот же приватный socket. Это позволяет восстановить тот же аккаунт, если браузер потерял сессионные cookies при перезапуске. Домен, путь, срок действия, Secure/Host-префиксы и SameSite проверяются повторно в worker; cookies неизвестной области и bootstrap без метаданных не переносятся. Затем аккаунт обязательно проверяется по ответу браузера. Адрес не сравнивается и не настраивается. Новая авторизация по телефону или коду не выполняется.

Нужны Chrome, Xvfb, сгенерированная системная локаль `ru_RU.UTF-8`, пользователь `ozonbrowser` и уже авторизованный профиль под `/var/lib/price-checker-ozon-browser/`. После установки release выполнить от root:

```sh
bash /opt/price-checker/current/scripts/setup-ozon-recovery.sh /var/lib/price-checker-ozon-browser/<saved-session>/profile
```

Socket доступен только `pricechecker`, профиль — только пользователю браузера. Приватная конфигурация пути находится в `/etc/price-checker-ozon-recovery.env` с правами 0600. Worker ограничен MemoryMax=1024M, MemoryHigh=896M, SwapMax=128M, CPUQuota=100%, TasksMax=256 и RuntimeMaxSec=1320. Сбор имеет собственный таймаут 590 секунд, окно входа — 20 минут на стороне приложения и 21 минуту в worker. Постоянного процесса браузера нет. Для сервера с 2 ГБ RAM это временный лимит, а не гарантия запуска при любом остатке памяти.

Установщик также сохраняет в этом файле `LANG=ru_RU.UTF-8`, `LC_ALL=ru_RU.UTF-8` и `LANGUAGE=ru_RU:ru`. Их наследуют Chrome в worker и отдельное серверное окно: русский язык интерфейса задаётся независимо от языка сайтов и HTTP-заголовка `Accept-Language`. Изменение применяется при следующем запуске браузера; системная локаль остальных служб не меняется.

При обновлении уже установленного worker нужно установить актуальный `scripts/systemd/price-checker-ozon-recovery@.service` в `/etc/systemd/system/` и выполнить `systemctl daemon-reload`; профиль и его конфигурацию заменять не требуется. Для отключения: `systemctl disable --now price-checker-ozon-recovery.socket`.

## Окружение браузера

Общий файл окружения также задаёт `TZ=Europe/Moscow`, `OZON_BROWSER_SCREEN=3840x2160`, `OZON_BROWSER_WINDOW=1282x1344`, `OZON_BROWSER_SCALE=1.5` и `OZON_BROWSER_GRAPHICS=swiftshader`. Размер Xvfb указан в физических пикселях: при масштабе 1,5 Chrome показывает `screen.width=2560` и `screen.height=1440`; внутренний размер страницы — `1282×1257`, как в локальном Chrome при сравнении. Список языков нового выделенного профиля задаётся через `intl.accept_languages` и `intl.selected_languages` в `Default/Preferences`: `ru,en-US,en,zh-CN`. Личный профиль Windows для этого не переносится.

`OZON_BROWSER_GRAPHICS=auto` включает обычный выбор графического backend. На текущей VDS в этом режиме WebGL оказался недоступен, поэтому установщик явно выбирает SwiftShader: с ним WebGL работает. Прежние отключения фоновой сети, обновления компонентов и синхронизации удалены. `--disable-blink-features=AutomationControlled` выравнивает `navigator.webdriver` с локальным Chrome, сохраняя управление через приватный CDP pipe. Настройка прокси, пропуск первого запуска и проверки браузера по умолчанию сохраняются. ОС Linux и виртуальное оборудование остаются отличными от Windows.

Для полноценного набора шрифтов на Ubuntu установить `fonts-noto-core`, `fonts-noto-color-emoji`, `fonts-dejavu-core`, `fonts-croscore`, `fonts-crosextra-carlito` и `fonts-crosextra-caladea`. Для смены профиля сначала закрыть серверный Chrome, создать отдельный каталог под `/var/lib/price-checker-ozon-browser/` с владельцем `ozonbrowser` и правами 0700, затем заменить только `OZON_BROWSER_PROFILE` в общем файле окружения. Прежний каталог сохраняется для возврата; история цен и привязка аккаунта не меняются. Новый профиль потребует входа владельца.

## Отдельный маршрут Ozon

`OZON_PROXY_URL=http://127.0.0.1:17891` задаёт один локальный HTTP-прокси для HTTP-сборщика Ozon и Chrome в recovery worker. Значение хранится в `/etc/price-checker-ozon-proxy.env` с правами 0600; HTTP-сборщику нужен этот файл через systemd drop-in основного приложения. Worker читает его через `EnvironmentFile`; отдельной службе серверного окна также нужен этот файл. При ошибке настроенного прокси прямого повторного подключения нет. Без переменной сохраняется обычное прямое соединение. Глобальный dispatcher Node.js не меняется.

На сервере выбран узел «Казахстан — 1»: `astana.vkusnews.com:443`, alias `eos-cd52253302e3`. При предыдущем открытии публичной главной страницы его выходной IPv4 был `83.229.15.247`; провайдер может позднее изменить адрес узла. Для него установлена отдельная служба `scripts/systemd/price-checker-ozon-proxy.service`: Mihomo слушает только `127.0.0.1:17891`, использует единственный узел и правило `MATCH` на него, без автоматического выбора и DIRECT fallback. Закрытая конфигурация `/etc/price-checker-ozon-proxy/config.json` содержит копию параметров этого узла из существующего provider и не хранится в репозитории. Основной прокси Telegram на порту 17890 и маршруты Randewoo остаются прежними.

Служба прокси включена в автозагрузку. Для `price-checker.service`, `price-checker-ozon-recovery@.service` и отдельного `price-checker-ozon-browser.service` установлены drop-in `ozon-proxy.conf` с `Wants=price-checker-ozon-proxy.service`, `After=price-checker-ozon-proxy.service` и `EnvironmentFile=/etc/price-checker-ozon-proxy.env`. После изменения маршрута основное приложение нужно перезапустить; Chrome получит настройку при следующем открытии. Установка маршрута не открывает браузер, не восстанавливает вход и не возобновляет приостановленный сбор.

## Проверки

20 октября 2026 по разрешению владельца выполнено сравнение браузерного окружения и повторное открытие Ozon. У нового выделенного профиля подтверждены экран `2560×1440`, масштаб `1.5`, размер страницы `1282×1257`, языки `ru,en-US,en,zh-CN`, часовой пояс `Europe/Moscow` и `navigator.webdriver=false`. Установлено 206 семейств шрифтов. В режиме `auto` WebGL недоступен; со SwiftShader он работает, поэтому на этой VDS выбран SwiftShader. В штатном серверном окне через Казахстан (`83.229.15.247`) загрузилась гостевая страница избранного без сообщения про VPN. Затем владелец вошёл вручную: приложение подтвердило прежний аккаунт, сохранило HTTP-сессию с правами 0600 и закрыло Chrome. Требование действий снято, существующее расписание возобновлено. Отдельный общий сбор после входа вручную не запускался. Прежний профиль сохранён для возврата.

Ранние эксперименты 18 октября 2026 подтвердили серверный профиль и схему HTTP 403 → Chrome → обновление cookies → HTTP 200, включая изолированную копию VDS. Это исторические проверки прежнего восстановления cookies.

Тесты новой схемы проверяют переключение всей очереди после одного HTTP 403, сохранение браузерных цен, одну сессию на обход, закрытие браузера, остановку на его отказе, проверку аккаунта/адреса/SKU, банковские условия, ограничения GET, размер ответа, явное ожидание источника и отмену socket. Длительная стабильность доступа не гарантируется; истёкший вход может потребовать участия владельца.
