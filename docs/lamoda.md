# Lamoda: независимое избранное

## Сбор с Android

Приложение и инструкция: [`apps/lamoda-android/README.md`](../apps/lamoda-android/README.md).
Телефон подключается одноразовым кодом на `/lamoda/android`. После подключения
задания Lamoda исполняются в WebView телефона; существующий Telegram-бот сообщает,
когда нужно открыть приложение. История обновляется только после получения всего
избранного и проверки аккаунта. Серверные браузер и прокси для такого сбора
запускать не требуется.

## Границы реализации

Lamoda использует отдельные `.data/lamoda/prices.sqlite3`, профиль Chrome,
службу, блокировку сборщика, очередь Telegram и облачные снимки. Перенос очереди
Ozon и разделение существующего общего бэкапа Randewoo/Ozon отложены владельцем.
Существующие расписания и данные магазинов сохраняются. Общие приложение,
авторизация Price Checker, оформление и Telegram-бот расширены третьим магазином.
Страницы просмотра браузера Lamoda нет.

Прямого HTTP-транспорта к Lamoda в Node нет: основной процесс обращается к
приватному Unix socket, а Chrome читает только GET `/wishlist/?page=N` в своём
авторизованном origin. Корзина, карточки, заказ и изменение избранного не вызываются.
Телефон и код владелец вводит непосредственно в серверном окне магазина.

## Наблюдаемый контракт

21 октября 2026 вручную открыто избранное в уже авторизованном локальном Chrome.
В ответе документа наблюдался `var __NUXT__` с JSON-строками `payload.state.user`
и `payload.state.payload`. Парсер извлекает эти JSON-члены, не исполняя код сайта.
Это исследование источника; браузерные тесты приложения не запускались.

- `user.customer.id` вместе с `is_active=true` подтверждает аккаунт;
  `customer=null` означает потерю входа. Отсутствующий/непонятный блок аккаунта
  считается временной ошибкой подтверждения, а не доказанным выходом.
- `user.wishlist[].product_sku` задаёт полный ожидаемый набор коротких SKU.
  Одна строка соответствует товару и цвету; размеры отдельно не отслеживаются.
- `payload.products` содержит названия, изображения, наличие и цены.
- Итоговая видимая цена — последнее звено `prices[].price`, при отсутствии цепочки
  используется `price_amount`. Наблюдавшаяся onsite-акция снижала итоговую цену
  относительно `price_amount`; корзинные промокоды не применяются.
- Зачёркнутая цена — первое звено цепочки цен при скидке, с резервным
  `old_price_amount`. При onsite-промо отдельное поле может отсутствовать,
  хотя зачёркнутая цена отображается. Равное текущей значение не зачёркивается.
  Все суммы переводятся в целые копейки;
  неизвестные значения остаются `null`. Поддержана только валюта RUB.
- `pagination` содержит `found`, `limit`, `offset`, `page`, `pages`.
  Наблюдались 253 избранных и пять страниц по 60 товаров. Переход «Дальше» использовал
  `/wishlist/?page=2`. Числа не закреплены в сборщике.

Каждая страница должна подтверждать прежний аккаунт и тот же полный набор SKU.
Повтор страницы, изменение состава во время обхода, пропущенный товар, фильтр
или незавершённая пагинация отменяют публикацию всего прохода. Предыдущий состав
сохраняется. Результат, наблюдения и событие Telegram публикуются одной транзакцией.
Лимит защиты — 1000 страниц и 100000 товаров; превышение даёт явную ошибку.

## История и ошибки

У наблюдения раздельны время проверки `checked_at` и исходная дата цены `price_at`.
При недоступности сохраняются последняя известная цена и её дата, наличие
перепроверяется при каждом общем сборе. После возврата сравнение продолжается
с прежней известной ценой. Повтор цены не сбрасывает дату последнего изменения.
Исчезнувшие из избранного товары сохраняют историю, но не входят в текущий список.

При временной ошибке, включая 403, остаётся включённое расписание; следующая
попытка назначается по нему с соблюдением Retry-After. Подтверждённая потеря входа
или чужой аккаунт требуют владельца. Ошибки записываются в SQLite и журнал службы
без cookies, тела ответа, телефона и кода. Ошибка одного прохода не запускает
немедленную цепочку повторов. Прерванные проходы восстанавливаются при запуске.

Расписание Lamoda изначально выключено, исходный интервал — 30 минут. Доступны
30/60/120 минут либо выбранные часы по Москве; 24:00 нормализуется в 00:00.
После простоя выполняется одна просроченная проверка.

## Сервер после слияния PR

Источник изменений — `develop` с upstream `origin/develop`. Владелец сливает PR
в main после проверки изменений и успешного CI; обязательных approvals — 0.
Штатный CI/CD развёртывает main.
До слияния runtime Lamoda на рабочий сервер не устанавливается.

Перед первым входом подключить отдельный WebSocket-маршрут Lamoda в Nginx:

```sh
install -m 644 /opt/price-checker/current/scripts/nginx/lamoda-login.conf /etc/nginx/snippets/price-checker-lamoda-login.conf
```

В HTTPS-блок `server` сайта Price Checker добавить одну директиву
`include /etc/nginx/snippets/price-checker-lamoda-login.conf;`, затем выполнить
`nginx -t` и `systemctl reload nginx`. Шаблон Ozon подключается отдельно.
Обычный маршрут приложения с `Connection ""` не передаёт WebSocket: без этого
правила окно Lamoda закрывается при подключении. Маршрут требует авторизацию
приложения и проверяет Origin; `access_log off` исключает токен окна из access log.
Тайм-аут Nginx — 25 минут, срок окна приложения остаётся 20 минут.
Последующие обновления приложения не заменяют системную конфигурацию Nginx.

После развёртывания сохранённой версии:

```sh
bash /opt/price-checker/current/scripts/setup-lamoda.sh
python3 /opt/price-checker/current/scripts/lamoda-resource-report.py --seconds 10
bash /opt/price-checker/current/scripts/setup-lamoda.sh --enable-browser
python3 /opt/price-checker/current/scripts/lamoda-resource-report.py --seconds 10
```

Служба работает от `lamodabrowser`, профиль находится под
`/var/lib/price-checker-lamoda-browser/profile`, socket —
`/run/price-checker-lamoda/browser.sock`, доступен группе `pricechecker`.
CDP передаётся через pipe, TCP-порт отладки не открывается. Chrome не закрывается
по простою. Служба имеет пределы MemoryHigh=640M, MemoryMax=768M, CPUQuota=100%.
Они ограничивают ущерб при росте потребления, но не доказывают достаточность памяти.

Виртуальный экран Xvfb — `1280x900x24`, окно Chrome — `1280x900` в позиции `0,0`.
Размеры совпадают, поэтому трансляция не включает большой пустой рабочий стол.
Они задаются при каждом запуске, включая перезапуск после закрытия окна входа.
Как в настройке Ozon, заданы `--use-gl=angle --use-angle=swiftshader` и
`--disable-blink-features=AutomationControlled`. Масштаб Chrome явно не фиксируется.
Эти параметры применяются при следующем запуске браузера из развёрнутой версии.

### Разовая запись неисправности браузера

`LAMODA_BROWSER_DIAGNOSTICS=1` включает запись первых 90 секунд работы Chrome:
сетевые ответы и ошибки, разрешённые диагностические заголовки с ID запросов,
исключения и сообщения Console страницы и подключённых workers, показатели cgroup.
В конце сохраняются метаданные страницы и снимок экрана. Запись сама не выполняет
переходы, клики, вход или сбор. Обычный запуск остаётся на `about:blank`.
Для одного открытия главной предусмотрено действие `diagnostic_start` через
приватный socket, доступное только при включённой диагностике и вне окна входа.

Файлы находятся в `/var/lib/price-checker-lamoda-browser/diagnostics/browser-*`
(каталог 0700, файлы 0600). Cookies, Authorization, тела отправляемых запросов и
query-параметры сетевых URL не записываются. HTML первых четырёх документов и
сообщения страницы остаются приватными: они могут содержать данные сессии.
Размер и длительность записи ограничены; ошибка записи не останавливает Chrome.

По явному поручению владельца доступна ручная установка браузера из сохранённого
`origin/develop`, без изменения основного релиза и служб Ozon:

```sh
git -C /opt/price-checker/repository fetch origin
bash /opt/price-checker/repository/scripts/setup-lamoda-browser-preview.sh
```

Если рабочий checkout ещё не содержит установщик, выполнить его непосредственно
из сохранённого `origin/develop`, предварительно разместив рядом его systemd-шаблон.
Установщик проверяет чистую `develop` с upstream `origin/develop`, сохраняет
неизменяемый снимок исходников и устанавливает drop-in только службы Lamoda.
Его путь и размеры сохраняются после перезапуска. Для возврата к релизу после
слияния выполнить обновлённый `setup-lamoda.sh`; затем перезапустить службу Lamoda.

Сравнить память, swap, средний CPU и ввод/вывод служб до/после запуска и во время
обычной работы сборщиков и бэкапа. Исходный read-only замер сервера перед
реализацией: 1799 МиБ RAM, около 864 МиБ доступны, 181 МиБ swap заняты.
Дополнительный расход постоянного Chrome Lamoda пока **не измерен**.
Скрипт измерений не запускает браузер или сборы.

Войти в Price Checker и открыть `/lamoda/login`: «Открыть Lamoda» открывает
в серверном окне `https://www.lamoda.ru/wishlist/`. Chrome загружает страницу,
но сборщик не извлекает и не отправляет товары и цены до сохранения входа или сбора.
Обычный запуск службы оставляет Chrome на `about:blank` до первого действия.
Выполнить вход в окне магазина и нажать
«Сохранить вход». Первое подключение закрепляет аккаунт; другой
аккаунт не заменяет существующую привязку. После подтверждения сохраняются scoped
cookies (0600), окно входа и интерактивный Chrome закрываются; обычный браузер
возобновляется с тем же выделенным профилем. Действующие cookies профиля имеют
приоритет над сохранённой копией; partition-контексты не смешиваются.
Временное VNC-окно доступно только на loopback через защищённый WebSocket приложения,
с проверкой сессии, Host/Origin и одноразового токена, не более 20 минут.
Для noVNC используется уже установленная библиотека удалённого окна; это общие
статические файлы, без доступа к профилю или аккаунту Ozon.

Серверный вход, чтение через Linux Chrome и нагрузка после запуска ещё требуют
подтверждения на рабочем сервере после слияния. Локальный вход не переносится.
Автосбор не включается установщиком или сохранением входа.

### Прокси Lamoda

Lamoda читает только свою переменную `LAMODA_PROXY_URL`. Допустим один локальный
HTTP endpoint вида `http://127.0.0.1:17892`; пустое или некорректное значение
останавливает запуск браузера без вывода самого значения. Без переменной
сохраняется прежний маршрут. Настройки `OZON_PROXY_URL` браузер Lamoda не читает.
Одинаковый маршрут применяется к окну входа и сбору избранного в этом Chrome.

Для отдельного российского выхода Lamoda используется проверенный узел WASP:

```sh
bash /opt/price-checker/repository/scripts/setup-lamoda-proxy.sh wasp-c8fd05c9561f
```

Нужны уже установленные Mihomo, curl, пользователь `priceproxy` и приватный каталог
WASP `/etc/price-checker-ozon-proxy/catalog.json`. Для прежних узлов EOS нужен
Python с PyYAML и provider `/var/lib/price-checker-proxy/providers/eos.yaml`.
Установщик выбирает ровно один узел из указанного каталога и создаёт независимую
`price-checker-lamoda-proxy.service`. Mihomo слушает только `127.0.0.1:17892`;
конфигурация с параметрами выбранного узла находится в
`/etc/price-checker-lamoda-proxy/config.json` (0600), состояние — в
`/var/lib/price-checker-lamoda-proxy`. Ключи не выводятся и не хранятся в Git.

По умолчанию выбран WASP `wasp-c8fd05c9561f`; 26 октября 2026 нейтральная проверка
подтвердила выход `213.176.19.20` (RU). Постоянный ID берётся из приватного
`/etc/price-checker-ozon-proxy/catalog.json` только для чтения; активный маршрут
Ozon и его Chrome не меняются. Можно передать другой постоянный `wasp-<id>` или
прежний `eos-<id>` единственным аргументом. Номера `wasp:3` после обновления
подписки могут измениться, поэтому установщик принимает постоянный ID.
Ранее EOS `eos-dd691bfb0441` давал выход `129.101.112.9` (RU), но проверка
26 октября 2026 не смогла подтвердить работу этого узла.
Перед изменением маршрута Chrome установщик проверяет конфигурацию Mihomo и
подтверждает страну RU через оба сервиса. Если проверка не удалась, он восстанавливает
прежнюю конфигурацию отдельного прокси и не переключает браузер.

После успешной проверки установщик записывает `LAMODA_PROXY_URL` в отдельный
`/etc/price-checker-lamoda-proxy.env` (0600) и устанавливает systemd drop-in
с обязательным `EnvironmentFile` и зависимостью от прокси Lamoda.
Он перезапускает только уже работающий браузер Lamoda: текущее окно входа закроется,
профиль и cookies сохранятся. Выключенный браузер и расписание не включаются.
Настройки Ozon, Randewoo, общего приложения и основного прокси не изменяются.

Chrome получает один `--proxy-server`, без `direct://` в списке резервных маршрутов,
и `--disable-quic`. При сбое прокси запрос завершается ошибкой; расписание
продолжает работу по обычным правилам. Такое поведение одного явно заданного
прокси описано в [документации Chromium](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md#manual-proxy-settings).
Сбой российского прокси затрагивает только Lamoda. Прокси Ozon на порту 17891 и
основной прокси на порту 17890 работают отдельными службами. Базы, браузерные
профили и расписания остаются раздельными.
Смена маршрута не подтверждает успешный вход и не гарантирует отсутствие капчи.

## Telegram и резервные копии

`/check_lamoda`, `/check`, `/status`, `/help` поддерживают Lamoda. Отчёты содержат
числа снижений/повышений, время МСК, ближайшую проверку и кнопку `/lamoda`;
подтверждённый выход — кнопку `/lamoda/login`. Эмодзи обычный 🛍️.
Очередь, повторы и отметки отправки находятся только в базе Lamoda. Каждая
завершённая проверка создаёт отчёт, включая одинаковые ошибки подряд. После сбоя
отмечается первый успешный результат. Возможен повтор сообщения при потере
подтверждения Telegram; строго однократная внешняя доставка не обещается.

```sh
bash /opt/price-checker/repository/scripts/setup-independent-backups.sh --enable
```

Это отдельная служба и таймер, использующие прежние настройки restic/rclone и
ключ шифрования. Новые секреты и репозиторий не создаются. Таймер проверяет
Lamoda раз в минуту на 30-й секунде, выполняет снимок после новых наблюдений и
не реже раза в час. Он не читает рабочие базы других магазинов. Весь файл SQLite,
включая очередь Telegram и настройки, копируется через Backup API.

Снимки имеют отдельный тег `price-checker-lamoda`, манифест
`price-checker-lamoda-backup-v1` и рабочий каталог
`/var/lib/price-checker-lamoda-backup`. Старые снимки/настройки Randewoo/Ozon и их
валидатор не меняются. Перед включением и затем ежедневно Lamoda восстанавливается
во временный каталог; проверяются SQLite, все таблицы, даты, размер и SHA-256.
Очистка затрагивает только точки Lamoda, сохраняет как минимум последнюю и
выполняется после проверки восстановления. Общий restic check/prune выполняет
`price-checker-backup-maintenance.service`. Три магазина и обслуживание используют
общую блокировку бэкапов, отдельную от очереди сбора цен; повторный запуск одного
магазина не накапливается. Установщик проверяет восстановление всех трёх магазинов
до отключения прежнего общего таймера Randewoo/Ozon, при ошибке возвращает прежние
инструменты и таймеры. Подробности — `docs/google-drive-backup.md`.
Недоступность общего Drive/restic по-прежнему может затронуть обе службы:
независимы результаты магазинов, но используется одно облачное хранилище.

Восстановление Lamoda выполняется только в новый отдельный каталог:

```sh
python3 /usr/local/lib/price-checker/lamoda-backup.py restore SNAPSHOT_ID --target /srv/lamoda-recovery
```

Рабочую базу команда не заменяет. После осознанного возврата старого снимка
нужно учитывать откат истории и состояния отправки сообщений. Секреты и профиль
Chrome в бэкап БД не входят. Перед деплоем база Lamoda дополнительно копируется
штатным deployment-скриптом при её наличии; ошибка обязательной копии останавливает
обновление. Для действующего SSH entrypoint требуется установка новой версии
`scripts/deploy.py` штатным `setup-deploy.sh` после слияния, как и при других
изменениях установщика.

## Проверки

Разрешены unit-тесты парсера, SQLite, сервиса, API, Telegram и CDP с имитацией,
Python-проверки бэкапа, frontend unit-тесты, typecheck, сборка и статический анализ.
E2E, Playwright/Selenium и тесты с реальным браузером не запускаются. Синтетические
фикстуры повторяют наблюдаемые поля, не содержат данные аккаунта или cookies.

## Chrome на Windows

`apps/lamoda-windows/launch-chrome.cmd` открывает одну вкладку избранного Lamoda
в отдельном постоянном профиле Chrome. Программа сразу завершается и не читает
содержимое страницы. Старое имя `collect-once.cmd` ведёт к тому же действию.
Удалённая отладка, сбор цен, опрос VPS и отправка снимков из Windows-программы
удалены. Автозапуск, если его отдельно установят, открывает одну вкладку при
входе в Windows и затем завершается.

Сохранённые ранее `desktop_snapshots`, `desktop_products` и
`desktop_observations` остаются в базе Lamoda. Страница `/lamoda/desktop`
показывает эту историю, но новый запускатель её не пополняет.
